# SAGPool — Self-Attention Graph Pooling Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Implement `SAGPool` (Lee, Lee, Kang — ICML 2019, https://arxiv.org/abs/1904.08082), a graph pooling layer that uses a GNN-computed self-attention score per node to select the top-`⌈kN⌉` informative nodes and pool the node features and adjacency.

**Architecture:** Three classes — `SAGPool(in_features, ratio=0.5, use_gcn=true)`, `SAGPoolHierarchical` (stack of `SAGPool` + `GCN` + readout for graph classification), and `SAGPoolGlobal` (single SAGPool + readout for graph classification). Implemented in `include/nn/layers/attention/sagpool.{h,cpp}` (placed under attention/ because the paper is structurally a self-attention mechanism adapted to graph pooling, mirroring where `gat.h` lives).

**Tech Stack:** C++17, hand-derived analytical backward, FD gradient checks at machine precision. Follows the GAT layer's interface pattern (constructor + `forward(X, A)` returning `(X', A')` + `backward(grad_X', grad_A', lr)` + `parameters()` / `gradients()` / `update_weights()` / `zero_grad()`).

## Paper recap (the only parts that matter)

**Algorithm** (Lee et al. 2019, Eq. 1–4 + Algorithm 1):
1. Compute attention score per node: `Z = softmax(GNN(X, A)) ∈ R^N` (PyG convention) or `Z = σ(GNN(X, A))` (raw paper formulation). We'll use `Z = softmax(GNN(X, A))` per the paper's official PyTorch reference — softmax is what makes "self-attention" a proper distribution, and the PyG reference uses softmax. The GNN is a single GraphConv: `GNN(X, A) = Â X W_pool`, where `Â = D̂^{-1/2}(A + I)D̂^{-1/2}` is the symmetrically-normalized adjacency with self-loops and `W_pool ∈ R^{in_features × 1}` is the learnable projection.
2. Pick top `⌈kN⌉` nodes by score: `idx = topk_idx(Z, ⌈kN⌉)`.
3. New features: `X' = (X ⊙ Z)_{idx, :} ∈ R^{⌈kN⌉ × in_features}` (per-node multiplication by score, then row-select).
4. New adjacency: `A' = A[idx, idx] ∈ R^{⌈kN⌉ × ⌈kN⌉}`.
5. Backward: chain through GCN → softmax → topk-mask → element-wise → row-select. The topk operation is treated as a **fixed mask** during backward (standard treatment, also used in the PyG reference implementation — `idx` is a hard assignment, no STE; gradients flow only to the selected nodes).

**Why this layer matters:**
- Graph U-Net building block (the "pool" in graph U-Net).
- Unlike random pooling (drop nodes uniformly), uses learned per-node importance scores.
- Unlike DiffPool (differentiable soft assignment), uses hard top-k — simpler, faster, often more accurate for graph classification.
- The score is computed via a GCN so it incorporates graph topology, not just node features.

**Distinguishing property vs the repo's existing graph layers (GAT, GATv2):** GAT/GATv2 produce per-EDGE weights for message passing. SAGPool produces per-NODE weights for *which nodes to keep*. They are orthogonal mechanisms and naturally compose: `GCN → GAT → SAGPool → GCN → ...`.

## Task 2: Implement `SAGPool` in `include/nn/layers/attention/sagpool.{h,cpp}`

**Objective:** Hand-derived forward + backward for SAGPool.

**Files:**
- Create: `include/nn/layers/attention/sagpool.h`
- Create: `include/nn/layers/attention/sagpool.cpp`

**Header** (`sagpool.h`): declare `SAGPool` class extending `Layer`. Public: `SAGPool(in_features, ratio=0.5, use_gcn=true)`, `forward(X)` returning `X'`, `forward_with_adj(X, A)` returning pair `{X', A'}`, `backward(grad_X', grad_A', lr)` returning `grad_X`, `update_weights`, `zero_grad`, `parameters`, `gradients`, accessors `in_features()`, `ratio()`, `use_gcn()`, `num_nodes_out(N)` → `⌈ratio*N⌉`. Private: `W_pool_ ∈ R^{in_features × 1}`, `grad_W_pool_` same shape, cached state from last forward (`last_X_`, `last_A_`, `last_A_hat_`, `last_Z_raw_`, `last_Z_`, `last_idx_`, `last_N_out_`, `last_in_features_`).

**Implementation** (`sagpool.cpp`):

*Forward (with adj):*
1. Validate `in_features > 0`, `0 < ratio <= 1.0`.
2. `N = X.rows`, compute `N_out = ⌈ratio * N⌉` (cast carefully: `(size_t)std::ceil(ratio * N)`).
3. **GCN score:** If `use_gcn=true`, compute `Â = D̂^{-1/2}(A + I)D̂^{-1/2}` where `D̂_ii = 1 + Σ_j A[i, j]` (with self-loops added). Then `Z_raw = ReLU(Â X W_pool)` (the paper's score layer; we add ReLU for numerical stability per the official PyG reference which uses `torch.nn.GCNConv` which applies ReLU inside). `Z = softmax(Z_raw)` across all N nodes.
   If `use_gcn=false`, `Z_raw = X W_pool`, `Z = softmax(Z_raw)`.
4. **Top-k selection:** Find the `N_out` indices with the largest `Z` values. Use `std::partial_sort` for O(N + N_out log N_out) work. Tie-break by lower index (stable, deterministic).
5. **Pool features:** `X'[i, j] = X[idx[i], j] * Z[idx[i]]` for i in [0, N_out), j in [0, in_features).
6. **Pool adjacency:** `A'[i, j] = A[idx[i], idx[j]]` for i, j in [0, N_out).
7. Cache `last_X_`, `last_A_`, `last_A_hat_`, `last_Z_raw_`, `last_Z_`, `last_idx_`, `last_N_out_`, `last_in_features_`, `last_X_out_` (for the row-select in backward).
8. Return `{X', A'}`.

*Backward:*
Given `grad_X' ∈ R^{N_out × in_features}` and `grad_A' ∈ R^{N_out × N_out}`:
1. **Scatter to the full X:** `grad_X_pooled ∈ R^{N × in_features}` is zero everywhere except `grad_X_pooled[idx[i], :] += grad_X'[i, :]`.
2. **Score gradient (element-wise chain):** `grad_X_pooled[idx[i], j] += grad_X'[i, j] * Z[idx[i]]` ... wait — the `X' = X ⊙ Z` is **row-wise multiplication**: each row `i` of `X'` gets multiplied by the scalar `Z[idx[i]]`. So `dL/d(X[idx[i], j]) = grad_X'[i, j] * Z[idx[i]]`, and `dL/d(Z[idx[i]]) = Σ_j grad_X'[i, j] * X[idx[i], j]`.
3. **Adjacency gradient:** `grad_A_pooled ∈ R^{N × N}` is zero everywhere except `grad_A_pooled[idx[i], idx[j]] += grad_A'[i, j]`. This is fed into the GCN backward as the gradient w.r.t. the GCN output (which we'll compute next) and the gradient w.r.t. `A` itself.

Actually, the `grad_A` flow here is subtle. SAGPool has TWO things depending on `A`:
- The score `Z` (via the GCN) depends on `A` through `Â`.
- The pool step doesn't directly depend on `A` (only on `X`, `Z`, `idx`).

So `grad_A` (full N×N) is **only** through the GCN chain. We handle `grad_A` as part of the GCN backward.

4. **GCN backward:** We need `dL/d(Z_raw)`, then chain through `softmax`, then chain through the GCN `ReLU(Â X W_pool)`.

Given `dL/d(Z)`:
- Compute `dZ = grad_Z_scatter` (the gradient w.r.t. `Z` at the indexed positions, zero elsewhere). This is from step 2's `dL/d(Z[idx[i]]) = Σ_j grad_X'[i, j] * X[idx[i], j]` term, gathered to the full N-vector.
- **Softmax backward:** `dL/d(Z_raw[k]) = Z[k] * (dZ[k] - Σ_m Z[m] * dZ[m])` (the standard softmax-backward identity `dz_k = z_k (dz_k - z · dz)`).
- **ReLU backward:** `dL/d(G_pre[k]) = (Z_raw[k] > 0) ? dL/d(Z_raw[k]) : 0` (the ReLU pre-activation is `G_pre = Â X W_pool`).
- **GCN pre-activation backward:**
  - `dL/d(W_pool) = X^T · dL/d(G_pre) ∈ R^{in_features × 1}` (treating `G_pre` as a vector of length N, with `G_pre[k] = Σ_{k',j} Â[k, k'] · X[k', j] · W_pool[j]`).
  - `dL/d(Â) = outer(dL/d(G_pre), (X W_pool)^T) = outer(dL/d(G_pre), G_pre^T)` ∈ R^{N × N}` (since `G_pre = Â X W_pool`, treating `X W_pool` as a column vector).
  - `dL/d(X) += Â^T · dL/d(G_pre) ∈ R^{N × in_features}` (chain through Â).
  - `dL/d(A)`: derived from `Â = D̂^{-1/2}(A + I)D̂^{-1/2}`. This is non-trivial because `D̂` itself depends on `A`. For simplicity (and following the paper's implementation which doesn't backprop through `D̂` w.r.t. `A`), we treat `D̂` as fixed during the backward pass — only the `(A + I)` part contributes to `dA`. Specifically: `dL/d(A[i, j]) += D̂^{-1/2}[i] · D̂^{-1/2}[j] · dL/d(Â)[i, j]` for the off-diagonal entries (self-loops don't count). The diagonal `A[i, i]` doesn't enter `Â` separately. We then add this to `grad_A_pooled` to get the total `grad_A`.

5. **Combine:** `grad_X = grad_X_pooled + Â^T · dL/d(G_pre)`. `grad_A` = scatter from `grad_A_pooled` + GCN chain (fixed-D̂ variant).
6. **Apply W_pool update:** `W_pool_ -= lr * grad_W_pool_` (already done by `update_weights(lr)`; `backward(..., lr)` just accumulates).
7. Return `grad_X`. (`grad_A` is exposed separately via `last_grad_A_` for callers who want it, but the standard `Layer::backward` interface only returns the input gradient.)

## Notes on hand-derived backward (the only non-obvious parts)

**`dL/d(Z[k])` from element-wise chain:** The forward has `X'[i, j] = X[idx[i], j] * Z[idx[i]]`. Differentiating w.r.t. `X[idx[i], j]` gives `Z[idx[i]]`, and w.r.t. `Z[idx[i]]` gives `Σ_j X[idx[i], j] * grad_X'[i, j]`. For non-selected nodes (`k ∉ idx`), `dL/d(Z[k]) = 0`.

**`dL/d(Z_raw[k])` from softmax:** Standard identity: given `dL/d(Z[k])`, `dL/d(Z_raw[k]) = Z[k] · (dL/d(Z[k]) − Σ_m Z[m] · dL/d(Z[m]))`. The `Σ_m` is the dot-product of `Z` with `dL/d(Z)`, which is a scalar we can precompute once.

**`dL/d(W_pool)` from the GCN pre-activation:** `G_pre[k] = Σ_{k', j} Â[k, k'] · X[k', j] · W_pool[j]`. So `dL/d(W_pool[j]) = Σ_k Â[k, k'] · X[k', j] · dL/d(G_pre[k])` ... wait, k' is summed over too in this formulation. Let me redo: `G_pre[k] = Σ_{k'} Â[k, k'] · (Σ_j X[k', j] · W_pool[j]) = Σ_{k'} Â[k, k'] · g[k']` where `g[k'] = Σ_j X[k', j] · W_pool[j] = (X W_pool)[k']`. Then `dL/d(g[k']) = Σ_k dL/d(G_pre[k]) · Â[k, k']`. And `dL/d(W_pool[j]) = Σ_{k'} dL/d(g[k']) · X[k', j] = X^T · dL/d(g)`. So `grad_W_pool = X^T · (Â^T · grad_G_pre)`.

Cleaner form: 
- `grad_G_pre ∈ R^N` is a vector
- `grad_W_pool = X^T · (Â^T · grad_G_pre) ∈ R^{in_features × 1}`
- `grad_X += (Â^T · grad_G_pre) · W_pool^T ∈ R^{N × in_features}` (chain through `g = X W_pool`)

**`dL/d(A)`:** Treated as `dL/d(A + I)`, with self-loops added back in. `grad_A_pre = D̂^{-1/2} · grad_Â · D̂^{-1/2}` (element-wise scaling per the symmetric normalization). The diagonal of `A + I` is 1 + `Σ_j A[i, j]`, so the `D̂` derivative contributes. We follow the PyG convention: skip the `D̂(A)` chain (treat `D̂` as fixed), so `grad_A[i, j] = D̂^{-1/2}[i] · D̂^{-1/2}[j] · grad_Â[i, j]` for `i ≠ j`, and `grad_A[i, i] = 0`. The diagonal of `A` is typically 0 anyway (no self-loops in input adj), and `A + I` contributes to `grad_Â` only off-diagonal.

## Mutation test plan (Task 1 #17)

The signature bug class for SAGPool is "forgot to multiply by Z when extracting X'". Naive impl writes `X' = X[idx]` (just row-select). The mutation is to revert to `X' = X[idx]` (drop the `* Z[idx]`). With this mutation:
- Forward shape still matches (3, 4).
- The element-wise check (test 7) WILL fail — the impl returns `X[idx[i], j]` not `X[idx[i], j] * Z[idx[i]]`.
- The FD input gradient test will also fail — because the analytical backward chain through `Z * X` becomes vacuous.

So the mutation catches itself in two places. Good.

## Risks + mitigations

- **Top-k stability:** `std::partial_sort` is stable across runs (deterministic given the same input). Tie-break: when two scores are equal, `partial_sort` returns the lower-indexed one first — this is well-defined and reproducible.
- **Softmax-over-N precision:** With N=10 nodes, the softmax should be well-conditioned. With very small scores, subnormals can occur but `Tensor::random(0.5)` gives scores in a healthy range.
- **`A + I` self-loop addition in backward:** Need to be careful — the forward adds self-loops to `A` BEFORE computing `D̂`, but the backward `grad_A` should NOT include a self-loop term (the input `A` had no self-loops; we only added them internally). So `grad_A[i, j]` for `i ≠ j` gets the `D̂^{-1/2}[i] · D̂^{-1/2}[j] · grad_Â[i, j]` term; `grad_A[i, i]` gets nothing (and is typically 0 anyway since input `A` has 0 diagonal).
- **`use_gcn=false` path:** No `A_hat` chain, just `Z_raw = X W_pool` directly. The backward is just softmax + W_pool gradient, much simpler.
