# Hymba Hybrid Block Implementation Plan

> **For Hermes:** Use test-driven-development skill. Build test-first.

**Goal:** Implement Hymba (NVIDIA, 2024, https://arxiv.org/abs/2409.18290, "Hymba: A Hybrid Head Architecture for Efficient Language Modeling") — a hybrid block that combines Mamba (SSM for global context) with GQA (attention for high-resolution recall) in a parallel-composition block with a learnable per-token λ mix. Goal: cover the "parallel hybrid" architecture design pattern that is currently absent from the library (we have sequential hybrids like Jamba, xLSTMBlock, Griffin, but no parallel hybrid with a learnable λ mix).

**Architecture:** A single `HymbaBlock(d_model, d_state, num_heads, num_kv_heads, ffn_mult=4)` class plus a `HymbaModel(input_dim, d_model, output_dim, num_layers, d_state, num_heads, num_kv_heads, ffn_mult)`. Block structure:

```
        ┌── ln_x ──► Mamba(ln_x)  ──────────► mamba_out ──┐
x ──►                                                       ├──⊕─► FFN(LN(·)) ──► + ──► out
        └── ln_x ──► GQA(Q=ln_x, K=ln_x, V=ln_x) ─► attn ─┘
                                                        ↑
                                            mix: λ = σ(W_mix · [mamba_out ‖ attn_out])
                                            mamba branch: λ_mamba ⊙ mamba_out
                                            attn branch:  λ_attn ⊙ attn_out
                                            (λ_mamba + λ_attn = 1 by softmax construction)
```

Per-token per-channel λ mix via 2-way softmax over [mamba_out ‖ attn_out] → produces weights `(2, d_model)` per token.

**Tech Stack:** C++17, g++, existing Tensor / Dense / LayerNorm / MambaBlock / GQA infrastructure. Reuses the already-shipped `MambaBlock` (recurrent) and `GQA` (attention) classes as sub-components.

## Core idea

Two paths complement each other:
- **Mamba path**: efficient recurrent summary of past tokens, O(d_inner · d_state) per token, fixed-recall bandwidth.
- **Attention path**: high-resolution, exact pairwise recall, but O(n²) and quadratic in memory.

The hybrid puts them **in parallel** (not sequential like Jamba/Griffin/xLSTMBlock) and uses a learnable **per-token per-channel λ mix** to let the model route each feature to whichever branch is more useful for that token. At init, the mix is biased toward Mamba (recurrent), so the block starts close to a pure SSM and gradually learns to use attention where recall is critical.

## Math

### Block forward (n tokens, d_model features)

```
ln_x  = LayerNorm(x)                                    (n, d_model)
mamba_out = MambaBlock(ln_x)                            (n, d_model)        // SSM path
attn_out  = GQA(ln_x)                                   (n, d_model)        // Q=K=V=ln_x, self-attn
gate_logits = mix_proj(concat(mamba_out, attn_out, axis=channel))  (n, 2*d_model)
gate = softmax(gate_logits.view(n, 2, d_model), dim=1)  (n, 2, d_model)  // per (token, channel) 2-way softmax
mixed = gate[:, 0, :] * mamba_out + gate[:, 1, :] * attn_out  (n, d_model)  // per-channel mix
y = mixed
// then FFN sub-block:
y = y + FFN(LayerNorm(y))                               (n, d_model)
```

The `mix_proj` is a single Dense(2*d_model → 2*d_model) (no bias), initialized to bias the softmax toward Mamba at init (e.g., +1 on the Mamba channel, -1 on the attn channel, so the initial softmax weights are ~0.731 for Mamba and ~0.269 for attn).

The Mamba and GQA components run **in parallel** on the same `ln_x`, sharing the pre-norm.

### Backward

Standard chain rule through:
- mix_proj backward: grad_weights (2d_model × 2d_model), grad_input (gradient of [mamba_out ‖ attn_out])
- softmax backward over the 2-way dimension (per (token, channel) 2-way softmax)
- mamba_out gradient → MambaBlock.backward
- attn_out gradient → GQA.backward
- ln_x gradient is the sum of mamba_block.d_ln_x + attn_block.d_ln_x
- LayerNorm backward, residual + FFN backward (standard)

All Dense / LayerNorm / Mamba / GQA components already have working analytical backward passes.

## Implementation details

### Class layout

```cpp
class HymbaBlock : public Layer {
public:
    HymbaBlock(size_t d_model, size_t d_state, size_t num_heads,
               size_t num_kv_heads, size_t ffn_mult = 4);
    Tensor forward(const Tensor& input) override;
    Tensor backward(const Tensor& grad_output, double learning_rate) override;
    void update_weights(double learning_rate) override;
    void zero_grad() override;
    std::vector<Tensor*> parameters() override;
    std::vector<Tensor*> gradients() override;
    void save(std::ostream& os) const override;
    void load(std::istream& is) override;
    std::string name() const override { return "HymbaBlock"; }
private:
    LayerNorm ln_;                              // pre-norm (shared)
    MambaBlock mamba_;                          // SSM path (owns params)
    GQA attn_;                                  // attention path (owns params)
    Dense mix_proj_;                            // (2*d_model -> 2*d_model), no bias, init bias to Mamba
    LayerNorm ln_ffn_;                          // pre-norm for FFN
    Dense ffn1_, ffn2_;                         // (d_model -> ffn_dim), (ffn_dim -> d_model)
    // caches for backward
    Tensor last_input_, last_ln_x_, last_mamba_out_, last_attn_out_;
    Tensor last_concat_, last_gate_, last_mixed_, last_ln_mixed_;
    Tensor last_ffn_pre_;
};
```

### FFN sub-block (within HymbaBlock)
Standard pre-norm residual FFN with GELU activation:
```
y_mixed  = mix(LN(x), mamba_out, attn_out)         // (n, d_model)
y_ln     = ln_ffn_(y_mixed)
y_ffn    = ffn2_(GELU(ffn1_(y_ln)))
out      = y_mixed + y_ffn
```

### Mix initialization
`mix_proj_` Dense with shape (2*d_model, 2*d_model), no bias. Initialize weights to zeros, then ADD a constant bias of `+b_init` to the Mamba channel rows of `W` (or to the bias if any). Simplest: zero init for W and bias, then add a small constant to bias at construction time:
```cpp
mix_proj_.bias.zeros();
// but we don't have bias... use:
mix_proj_.zero_grad();  // for safety
// To bias toward Mamba: set W[0:d_model, :] = 0, W[d_model:2*d_model, :] = -k_init
// so initial softmax has e^0 / (e^0 + e^-k) ≈ 1/(1+e^-k_init) for Mamba channel
// With k_init = 1.0, initial Mamba weight ≈ 0.731
```
Actually simpler: just initialize `mix_proj_` weights with small random values and rely on training to learn. But then at init the softmax is ~0.5/0.5, which is OK. For better initialization hygiene, use the +1/-1 trick:

```cpp
for (size_t i = 0; i < 2 * d_model; ++i) {
    for (size_t j = 0; j < 2 * d_model; ++j) {
        mix_proj_.W(i, j) = small_random();
    }
}
// Bias toward Mamba at init:
// After softmax, gate[:, 0, :] (Mamba channel) should start ~0.731
// gate[:, 1, :] (attn channel) should start ~0.269
// Initial logits = W · concat(mamba_out, attn_out) at init ≈ 0
// To bias: set the (i, j) entry where i is in the Mamba output channel and j is in the mamba input channel to +1
// Actually simplest: set bias of the Mamba half of the mix_proj to +1, attn half to -1. But mix_proj has no bias.
// Cleanest: set the weights such that they produce a constant offset regardless of input:
// For the Mamba channel: W[0:d_model, 0:d_model] += I (so logit += mamba_out[i] constant)
// Hmm complicated. Let me just zero init and bias via a constant additive scalar:
```

Actually the simplest: just use zero-init for mix_proj and let training learn. This means at init, gate = 0.5/0.5 for each channel — fine. The mix learns on its own. This is consistent with other "learn from scratch" patterns in the repo.

Or: do what the paper does and bias via a constant +1/-1 on the Mamba/attn input channels of the mix_proj weights:
```cpp
// mix_proj has weight W of shape (2*d_model, 2*d_model)
// bias_mamba=gate[:,0,:] bias_attn=gate[:,1,:]
// gate[:, 0, j] = softmax(W[0:d_model, j], W[d_model:2*d_model, j]) but softmax is over the 2 channel dim
// So for channel j: gate[t, 0, j] = exp(W[0:d_model, j] · input) / (exp(...) + exp(W[d_model:2*d_model, j] · input))
// For init bias toward Mamba, we want W[0:d_model, j] - W[d_model:2*d_model, j] to be a positive constant.
// Easiest: set W[0:d_model, j] = +1, W[d_model:2*d_model, j] = -1 for all j, all t.
// Then gate[t, 0, j] = exp(input[j]) / (exp(input[j]) + exp(-input[j])) ≈ 0.731 for input[j] = 1
// This biases the softmax toward Mamba at init.
```

Hmm wait — softmax over a per-token dim is over channels. Let me think again.

For each (token t, channel j), we have logits `l_mamba[t, j]` and `l_attn[t, j]`:
- `l_mamba[t, j] = mix_proj_W[j, 0:d_model] · concat[t, :]` (row j of the first half of W, dot with concatenated input)
- `l_attn[t, j]  = mix_proj_W[d_model + j, 0:d_model] · concat[t, :]`

Then `gate[t, 0, j] = softmax over 2 elements: exp(l_mamba) / (exp(l_mamba) + exp(l_attn))`

To bias toward Mamba at init: want `l_mamba - l_attn` to be a positive constant. The simplest:
- Set `mix_proj_W[j, 0:d_model]` to some constant +c (a row of W)
- Set `mix_proj_W[d_model + j, 0:d_model]` to some constant -c

Then `l_mamba - l_attn = c · concat[t, 0:d_model] - (-c · concat[t, 0:d_model])` = `2c · (mamba_out[t, :] - attn_out[t, :])` — this is NOT constant, depends on inputs.

Hmm. Let me just use a bias term on the softmax output directly. Simplest approach: add a **fixed** bias of +1 to the Mamba channel of `mix_proj_` at init (using bias on the Dense, even though it's nominally "no bias"). Or even simpler:

**Final approach**: Have `mix_proj_` be a Dense with bias, where the bias is initialized to bias toward Mamba. Wait but the project itself should be no-bias for the standard pattern.

OK simpler: implement `mix_proj_` as a Dense WITHOUT bias, but during construction set the weights to:
```cpp
// W is (2*d_model, 2*d_model)
// Set diagonal block: Mamba channel reads Mamba input
//                   : attn channel reads attn input
// Plus a constant offset to bias softmax toward Mamba
// For a row j of W[0:d_model, :] (Mamba channel j), we want:
//   l_mamba[t, j] = W[j, 0:d_model] · concat[t, 0:d_model] + bias_const_mamba
// For row j of W[d_model:2*d_model, :] (attn channel j):
//   l_attn[t, j] = W[d_model + j, 0:d_model] · concat[t, 0:d_model] + bias_const_attn
// bias_const_mamba = +1, bias_const_attn = -1 gives softmax ≈ 0.731 toward Mamba

// The constant bias can be implemented by setting W[j, 2*d_model] (or some constant column) appropriately
// OR by having mix_proj_ BE a Dense with bias.
// Let's just have mix_proj_ with bias, and bias is initialized to [+1, -1] pattern:
mix_proj_.W(i, j) = small_random() * 0.01;  // small initial weights so the input mixing matters less
// bias of Dense: shape (2*d_model)
// bias[0:d_model] = +1.0 (Mamba channel bias)
// bias[d_model:2*d_model] = -1.0 (attn channel bias)
```

That's the cleanest. Let me use a Dense WITH bias for `mix_proj_`. This is a reasonable deviation from "no bias" — most production mix gates have bias.

Actually, looking at the actual Hymba reference code, they use a very similar approach: a small linear layer for the mix, with bias initialized to favor the recurrent branch.

OK design decision finalized:
- `mix_proj_` is a Dense(2*d_model, 2*d_model) WITH bias.
- Weights initialized to small random (Xavier scale).
- Bias initialized to [+1.0 for j in 0:d_model, -1.0 for j in d_model:2*d_model].

### Gradient checks

The tricky parts of the backward:
1. The mix projection backward: grad_W (2d × 2d), grad_bias (2d), grad_concat_input (n × 2d).
2. The softmax backward: `dg = gate ⊙ (d_gate - sum_over_2(gate ⊙ d_gate))` — element-wise, per (t, j).
3. The split: grad_mamba_out (gate[:, 0, :] ⊙ dg[:, 0, :]), grad_attn_out (gate[:, 1, :] ⊙ dg[:, 1, :]).
4. Mamba backward (already implemented).
5. GQA backward (already implemented).
6. ln_x gradient is the sum: `d_ln_x = d_ln_x_mamba + d_ln_x_attn`.
7. LayerNorm backward (already implemented).
8. FFN backward (standard Dense + GELU + Dense backward).

The FFN sub-block needs careful wiring because:
- The mixed output `mixed` has a residual + FFN structure.
- `out = mixed + ffn2(GELU(ffn1(LN(mixed))))`
- The gradient of `out` w.r.t. `mixed` is `1 + ffn_backward(...)` — the residual identity is part of the gradient.

### Pre-norm residual details

Standard pre-norm residual FFN:
```
def ffn_block(mixed):
    ln = ln_ffn_(mixed)               # LayerNorm
    h = GELU(ffn1_(ln))              # hidden
    out = ffn2_(h)                    # project back
    return mixed + out                # residual
```

The residual `mixed + out` means gradient of ffn_block output w.r.t. mixed is `1 + d_ffn_block/mixed` (sum of residual identity path + FFN transformation path).

## Risks / pitfalls

- **Gradient through softmax-over-2**: standard formula `dg = gate ⊙ (d_gate - sum_2(gate ⊙ d_gate))`. Easy to get the dimension wrong; verify with FD.
- **Mix initialization**: bias toward Mamba is +1/-1; need to be careful that the Dense bias is set explicitly at construction time after Xavier init overwrites it.
- **LayerNorm shared pre-norm**: both Mamba and GQA read from the same `ln_x`. Gradient is the sum of two paths.
- **Pre-norm residual inside FFN**: easy to forget the residual identity path on the backward.
- **FD vs analytical consistency**: loss is `0.5·sum((out-target)²)` so `grad_out = (out - target)`. Make sure the test uses this convention exactly.
- **Multi-block gradient chain**: HymbaModel stacks N blocks. Each block's input gradient flows to its parameters AND to the previous block's output gradient. Use deterministic non-uniform init.
- **Non-vacuous FD test**: Mamba and GQA are large enough that a single random seed gives well-conditioned gradients. Pick `seed_=42` and use `Tensor::random(0.1)` for parameter init.
