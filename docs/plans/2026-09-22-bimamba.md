# Bidirectional Mamba (BiMamba) Implementation Plan

> **Status:** Implementation complete (45/45 focused tests pass).
> **Date:** 2026-09-22.

## Goal

Build a Bidirectional Mamba sequence mixer — `MambaBidirectional(d_model, d_state, d_inner=0)` — that composes two independent Mamba scans (forward on `x`, backward on the time-reversed input) and combines their gated outputs via a learnable per-(token, channel) 2-way softmax mix. Bidirectional context is the standard pattern in Vision Mamba (Zhu et al. 2024, §2.2) and Audio Mamba for non-causal modeling of images/audio.

## Architecture

```
            ┌── forward_mamba.forward(x)         ── y_f[T, d_inner]
input x ────┤
[T, d_model]│   x_rev[t] = x[T-1-t]
            └── backward_mamba.forward(x_rev)    ── y_b[T, d_inner]

mix_input = concat(y_f, y_b) [T, 2*d_inner]
mix_logits = mix_proj.forward(mix_input)         [T, 2*d_inner]
mix[t, 0..d_inner] = softmax over 2 (per channel j)
gated_out[t, j] = mix[t, j] · y_f[t, j] + mix[t, j+d_inner] · y_b[t, j]
output = out_proj_.forward(gated_out)            [T, d_model]
```

`mix_proj : R^{2·d_inner} → R^{2·d_inner}` (Dense), `out_proj_ : R^{d_inner} → R^{d_model}` (Dense).
Two independent `MambaBlock` instances (no weight sharing — the paper finds tied weights underfit).

## Critical Bug Found & Fixed

The initial implementation passed `grad_y_f` directly to `MambaBlock::backward`, treating it as `dL/d(MambaBlock's full output)`. **But BiMamba's `grad_y_f` is actually `dL/d(MambaBlock::last_gated_)`** — the pre-out_proj gated output, which BiMamba uses directly via its own `out_proj_` Dense.

The result: MambaBlock was re-applying its out_proj chain on a gradient that already represented `dL/dgated`, corrupting the in_proj / D_skip / A_log gradients by 50–100% (visible as rel_err > 1.0 in the FD checks).

**Fix:** added `MambaBlock::backward_from_gated(grad_gated, lr)` that takes `dL/dgated` directly and skips the out_proj chain. The original `backward(grad_output, lr)` is preserved (it correctly chains through out_proj). Both paths share a new private helper `backward_impl(grad, lr, input_is_gated)`.

Diagnostic trail:
- Before fix: forward_mamba `in_proj.weights[0][0]` FD rel_err = 1.43 (grad-sign-flipped); input gradient FD max rel_err = 9.06e-1.
- After fix: 8.5e-9 (in_proj) and 2.99e-6 (input gradient) — machine precision.

This is the kind of bug the systematic-debugging skill flags in section 5d (function not called / wrong call-site chain). It's also a "two-distinct-quantities-in-one-buffer" trap: the same `MambaBlock::backward` method is being asked to compute two different gradients depending on whether the caller has its own out_proj (BiMamba) or not (standalone MambaBlock).

## Test 8 (Time-Symmetry) Removed

The original Test 8 expected that reversing the input would time-reverse the output (a natural property of bidirectional models with time-symmetric recursions). This property **does NOT hold** for Mamba-1 because:
1. `Δ_t = softplus(dt_proj(x_t))` is input-dependent → forward sees x_0 first, backward sees x_{T-1} first.
2. The selective SSM recurrence is NOT exactly time-reversal invariant under this asymmetry.
3. The mix depends on `mix_proj.weights · [y_f ‖ y_b]`, which also isn't time-reversal invariant under random init.

For the property to hold exactly you'd need: `dt_proj.bias = 0` AND x being a palindrome AND specific mix_proj.weights structure — none of which BiMamba guarantees.

So Test 8 was a wrong-spec test and was removed (with explanatory comment).

## Test 15 (mix_proj.weights FD) — Combined Criterion

At certain random seeds, the `mix_proj.weights[0][0]` gradient is at the float64 noise floor (~1e-10). FD vs analytical: `ana=7.46e-10 fd=7.47e-10 rel_err=1.33e-3`. The relative error is high only because both values are tiny. **Fix:** use a combined criterion `rel_err < 1e-2 OR abs_diff < 5e-9` — either the relative error is reasonable, OR the absolute difference is small enough that it's clearly noise.

## Conventions Match Existing Codebase

- Per-(token, channel) 2-way softmax — same as `Hymba`'s `mix_proj` pattern
- Time-reversal chain `grad_x[t] = grad_x_fwd[t] + grad_x_rev[T-1-t]` — same as `lstm_bidirectional.cpp`
- Two independent `MambaBlock` instances — matches paper §2.2 "no weight sharing"
- `mix_proj.bias = 0` at init → uniform 0.5 mix — matches paper §2.2
