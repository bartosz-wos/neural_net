# Yogi Optimizer — Implementation Plan

> **For Hermes:** Implement with TDD using subagent-driven-development or directly in this session. Single file pair + test file + Makefile/nn.h wiring.

**Goal:** Add a `Yogi` optimizer class to the standard adaptive-optimizer lineup. Yogi is a well-known Adam variant (Zaheer et al. 2019, "Adaptive Methods for Nonconvex Optimization", https://papers.nips.cc/paper/2019/hash/adaedb1dfcccb1e1f4ce16e299c2e08c-Abstract.html) that self-corrects Adam's `v_t` drift on non-stationary objectives by replacing `(1-β2)·g_t²` with `(1-β2)·sign(v_{t-1} - g_t²)·g_t²`. Google uses it for BERT and large-scale training. It is a logical counterpart to the existing AdaBelief / Adamax / Adafactor / LAMB / Lion / Sophia set.

**Architecture:**
- `Yogi` class derived from `Optimizer` (matches the existing `AdaBelief` / `Adafactor` / `AdamW` style).
- Algorithm per parameter, with AdamW-style decoupled weight decay:
  ```
  m_t   = β1 · m_{t-1} + (1 − β1) · g_t
  v_t   = v_{t-1} − (1 − β2) · sign(v_{t-1} − g_t²) · g_t²     (the Yogi modification)
  m̂_t  = m_t / (1 − β1^t)
  v̂_t  = v_t / (1 − β2^t)
  param = param − lr · (m̂_t / (sqrt(|v̂_t|) + ε) + wd · param)
  ```
  `v_t` can become transiently negative under this update (the paper's Algorithm 2 allows this); use `sqrt(|v̂_t|) + ε` in the denominator so the step is always finite.

**Tech Stack:** C++17, `Tensor`/`Layer`/`Model`/`Optimizer` in this repo, no external deps. Verified by `check_gradient` / `check_gradient_mse` against centered finite-difference gradients *w.r.t. loss*, and a stochastic training step that reduces loss.

**Yogi vs other optimizers (one-line signatures from this repo):**
- **Adam** (`optimizer.h`): `v_t = β2·v_{t-1} + (1-β2)·g²` — fixed EMA of squared gradient.
- **AdaBelief** (`adabelief.h`): `s_t = β2·s_{t-1} + (1-β2)·(g − m_{t-1})²` — variance of gradient residual.
- **Yogi** (this PR): `v_t = v_{t-1} − (1−β2)·sign(v_{t-1} − g²)·g²` — self-correcting control rule.

The Yogi `v_t` update is purely additive in `(1−β2)·g²` (positive-definite growth in magnitude), unlike Adam whose `v_t` is a true EMA and can stall/lag.

**Verification:**
- 30+ checks pass at machine precision or with deterministic tolerance:
  - API/validation (lr/b1/b2/eps/wd accessors, default values, throws on `b1`/`b2` ≥ 1 or ≤ 0, throws on `eps ≤ 0`).
  - State shape correct on first step; lazy-init per layer.
  - First-step **sign-flip behavior** (the core Yogi property): if the per-coord update is `−(1−β2)·sign(v_{t-1}−g²)·g²` and `v_{t-1}=0`, then `v_1 = +(1−β2)·g²` regardless of sign of `g` (proves the modification).
  - When `v_{t-1}` is huge vs `g²`, `v_t` *decreases* (proves the control direction is right).
  - When `v_{t-1}` is tiny vs `g²`, `v_t` *increases*.
  - Bias correction: `m̂_t = m_t / (1−β1^t)`, `v̂_t = v_t / (1−β2^t)` exact at t=1.
  - Adam-style MSE-gradient check via `check_gradient_mse`: with `wd=0`, the param-grad-wrt-loss should match centered-FD gradient of the MSE loss to ≤ 1e-3 relative.
  - Weight-decay check: `param` strictly decreases when `wd > 0` and gradient is zero.
  - Determinism: two fresh `Yogi` instances with the same model+sequence of grads produce identical parameter updates bit-for-bit.
  - End-to-end training: 60 steps of `Yogi` on a 1-D linear regression task should reduce MSE loss to <50% of step-0 loss.
  - **Non-vacuousness**: a mutation that zeroes out `sign(v_{t-1}−g²)` (reducing to `−(1−β2)·g²` regardless) must break at least the first-step-sign and v-decrease tests. A mutation that flips the sign (`+(1−β2)·sign(...)·g²`) must also be caught.
- `make tests` and `make run_tests` both pass without regression.

### Task 3: Implement the v_t modification (the Yogi "soul")

**Objective:** Implement `v_t = v_{t-1} − (1−β2)·sign(v_{t-1} − g²)·g²` per coordinate.

**Step 1:** Inside `update_param`:
```cpp
double g2 = g * g;
double delta = v_prev - g2;
double v_new = v_prev - (1.0 - b2) * ((delta > 0) ? 1.0 : (delta < 0) ? -1.0 : 0.0) * g2;
// ↑ delta == 0 is theoretically mass-zero but choose 0 (no-op) on ties.
```

**Step 2:** Re-derive the empirical test cases:
- t=1, v_prev=0, g=2: `delta = 0-4 = -4 < 0`, sign = -1 ⇒ `v_new = 0 - (1−β2)·(−1)·4 = +(1−β2)·4`. Matches the test "first-step v is positive regardless of g's sign".
- v_prev=100, g=1: `delta = 100−1 = 99 > 0`, sign = +1 ⇒ `v_new = 100 − (1−β2)·1`. Matches "v decreases when v_prev dominates".
- v_prev=0.001, g=2: `delta = 0.001−4 < 0`, sign = -1 ⇒ `v_new = 0.001 + (1−β2)·4 > 0.001`. Matches "v increases when g² dominates".

**Step 3:** Add these three deterministic tests. Run; expect pass.

### Task 4: Bias correction + Adam-style update + weight decay

**Objective:** Wire the bias correction, the `m̂_t/(sqrt(|v̂_t|)+ε) + wd·param` step, end-to-end.

**Step 1:** Implement the full `update_param` body:
```cpp
double m_new = b1 * m_prev + (1 - b1) * g;
// (v_new computed above)
double m_hat = m_new / b1_c;
double v_hat = v_new / b2_c;
double denom = std::sqrt(std::abs(v_hat)) + eps;
double step = m_hat / denom;
if (wd > 0) (*param)[i][j] -= lr * wd * (*param)[i][j];
(*param)[i][j] -= lr * step;
```

**Step 2:** Tests:
- After 1 step with `lr=0.1, b1=0.9, b2=0.999, eps=1e-8, wd=0` on a 1-D test with `grad=2, m_prev=0, v_prev=0`:
  - `v_new = 0.001·4 = 0.004` (since sign of `0-4=-4` is `−1`, `−(1-0.999)·(−1)·4 = +0.004`).
  - `m_new = 0.9·0 + 0.1·2 = 0.2`.
  - `m_hat = 0.2/(1-0.9) = 2.0` (with t=1, b1_c = 1-0.9 = 0.1 → m_hat=2).
  - `v_hat = 0.004/(1-0.999) = 4.0`.
  - `denom = sqrt(4) + 1e-8 ≈ 2`. `step = 2/2 = 1`. `param = 0 - 0.1·1 = -0.1`. Tolerance 1e-9.
- With `wd=0.01` and `grad=0`: `m_new=0, v_new=0`, so `step = 0/(0+eps) = 0`, but weight decay still fires: `param -= lr·wd·param = -0.001·param`. Tolerance 1e-12.

**Step 3:** Run tests; both pass.
