# Soft MoE (Mixture of Experts via Soft Slot Dispatch) Implementation Plan

**Goal:** Add `SoftMoELayer` and `SoftMoEModel` — Puigcerver et al. 2024,
ICLR 2024, "From Sparse to Soft Mixtures of Experts"
(https://arxiv.org/abs/2308.00951). A fully-differentiable alternative to
top-k sparse MoE: each token is soft-dispatched into a fixed bank of
expert "slots", and slot outputs are soft-combined back into tokens.

**Why this matters:** Whereas Switch / DeepSeekMoE / sparse_moe.cpp use a
**hard** top-k selection per token (which is non-differentiable w.r.t.
the gate), Soft MoE replaces it with a **soft** assignment matrix. Every
expert slot sees a learned linear combination of all input tokens, and
every output token is a learned linear combination of all expert outputs.
This makes the gate fully differentiable (no straight-through estimator
needed), gives gradient flow to every (token, slot) pair, and often
matches or beats sparse MoE at the same parameter budget.

**Architecture:**

Given input `X ∈ R^(T × d_model)`, `num_experts` experts each with
`slots_per_expert` slots, expert hidden dim `d_expert`:

```
# 1. Compute dispatch weights D ∈ R^(T × E·S) via per-slot linear:
D_logits = X @ W_disp^T        # (T, E*S)   W_disp is (E*S, d_model)
D = softmax(D_logits, dim=1)   # softmax per-row -> probabilities over slots

# 2. Form slot inputs X' ∈ R^(E·S × d_model) as weighted sums of tokens:
X' = D^T @ X                   # slot_i = sum_t D[t, i] · X[t, :]

# 3. Apply each expert to its own slot:
for e in 0..E-1:
    for s in 0..S-1:
        Y_e_s = expert_e(X'_e_s)        # (d_model,) each

Y_stack = stack all (E*S, d_model)

# 4. Compute combine weights C ∈ R^(E·S × T):
C_logits = Y_stack @ W_comb^T    # (E*S, T)   W_comb is (T, E*S·d_model)
C = softmax(C_logits, dim=1)    # softmax over tokens per slot

# 5. Output as weighted sum of slot outputs:
output = (C^T ⊙ X) summed — actually:
output[t, :] = sum_{e,s} C[e*S+s, t] · Y_stack[e*S+s, :]    # (T, d_model)
```

In matrix form: `output = C^T @ Y_stack` where `C ∈ R^(E·S × T)`.

Note: the paper computes `C` from the slot inputs `X'` (not `Y_stack`)
and uses one `W_comb` shared across all experts/slots. To stay close to
the paper's "one router for all slots" design, we use:
- `W_disp : (E*S, d_model)` for dispatch
- `W_comb : (T, E*S*d_model)` for combine — actually this is
  parameter-heavy. We use the simpler form: `W_comb : (E*S, d_model)` so
  `C_logits = X' @ W_comb^T` (per-slot scalar combine per token), giving
  `C ∈ R^(E·S × T)` via softmax per slot. This is the "shared-by-slot"
  variant used in many reference implementations and matches the
  semantics: each slot learns which tokens it attends to.
