# BitNet b1.58 — Ternary Linear Layer Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Add a `BitLinear` (and `BitNetBlock`) layer that implements Ma et al. 2024's 1.58-bit weight quantization (W ∈ {-1, 0, +1} via absmean), with Straight-Through Estimator (STE) backward through the round() so the ternary projection is a drop-in replacement for `Dense` that trains via standard SGD.

**Architecture:** Per-row absmean quantization on the stored fp32 weights `W ∈ R^{d_out × d_in}`, producing `W_q ∈ {-1, 0, +1}` with a per-row scale `scale_w[o] = mean_j |W[o, j]|`. Forward: `Y = X · W_q^T · scale_w[o]`. Backward uses STE: gradient passes through `round()` unchanged for the in-range input (`|W/scale_w| ≤ 1`) and is zero at the clamp boundary — implemented via a mask `M[o, j] = 1 if |W[o,j]| ≤ scale_w[o] else 0`.

**Tech Stack:** C++17, Tensor (existing), Layer (existing), TinyTest harness pattern (LoRA-style).

**Why 1.58-bit, not full BitNet:** v1 implements the canonical BitLinear (weight-only ternary). Activation 8-bit absmean quantization from the paper §3.2 is **left for v2** — it adds a second quantization step that is non-trivial to make differentiable, and the ternary weight path is already the paper's distinguishing contribution. Plan notes this in code comments.

## BitLinear Math (paper §3.1–3.2)

**Per-row absmean scale** for `W ∈ R^{d_out × d_in}`:
```
scale_w[o] = (1/d_in) * Σ_j |W[o, j]|       // per-row mean absolute value
W_hat[o, j] = clamp(W[o, j] / scale_w[o], -1, +1)
W_q[o, j]   = round(W_hat[o, j])           // ∈ {-1, 0, +1}
```

**Forward** (paper Eq. 4):
```
Y = X · W_q^T · diag(scale_w)             // shape (N, d_out)
   = X · (scale_w[o] · W_q[o, j])_{o, j}^T
```

Note: `scale_w` is per-OUTPUT unit (paper convention, §3.1). `W_q[o, j]` carries the {-1, 0, +1} weights; `scale_w[o]` is broadcast over the j index.

**STE backward** (paper §3.2):
```
dL/dW = dL/dW_q · ∂W_q/∂W  (via STE)
∂W_q/∂W ≈ 1/scale_w[o]   if |W[o,j]/scale_w[o]| ≤ 1
            0             otherwise   (the clamp boundary)
```
So:
```
grad_W[o, j] = grad_W_q[o, j] · M[o, j] / scale_w[o]
where M[o, j] = 1 if |W[o, j]/scale_w[o]| ≤ 1, else 0
```

**Matmul-derivative backward** (paper Eq. 5 + standard chain rule):
Let `Z = X · W_q^T` (shape N×d_out) and `Y[o] = scale_w[o] · Z[o]`. Then:
```
grad_Z[n, o] = grad_Y[n, o] · scale_w[o]                    // (N, d_out)
grad_W_q[o, j] = grad_Z[:, o]^T · X[:, j] = Σ_n grad_Z[n, o] · X[n, j]   // (d_out, d_in)
grad_X[n, j]   = grad_Z[n, :] · W_q[:, j]                   // (N, d_in)
grad_scale_w[o] = Σ_n grad_Y[n, o] · Z[n, o]                // (d_out,) — optional, paper Eq. 5
```

The `grad_scale_w` is paper §3.2 (it shows the scale is learned jointly). I'll include it as a learnable parameter (one row-scale per output unit) but its gradient has a closed form — won't dominate test count.

## Task 4: update_weights + zero_grad + STE mutation test

**Objective:** Standard SGD update on W and scale_w, plus the STE mutation test that verifies the design is correct (not vacuous).

**Step 1: Test 9 — update_weights moves W** (after one backward, lr=0.01, W changes by |lr * grad_W|).
**Step 2: Test 10 — update_weights moves scale_w** (after backward, scale_w changes).
**Step 3: Test 11 — zero_grad clears all grads**.
**Step 4: Test 12 — STE mutation**: replace `round()` with `identity()` (i.e. drop the quantization). With identity, the layer becomes `Y = X · W^T` (a standard Linear), so the analytical backward should be the standard matmul backward. But under our STE implementation, if `round()` is identity, then `W_q = W` (the actual W, NOT ternary), so the STE mask still applies — but the input gradient chain through W_q is now `grad_X[n, j] = Σ_o grad_Z[n, o] * W[o, j]` (standard matmul backward, since W_q = W). The point of this test: it's a MUTATION-style check. The real test is: W_q ∈ {-1, 0, +1} (Test 3), and forward shape/FD grad pass. If we deleted the round() entirely, W_q would NOT be ternary and Test 3 would fail. So the test is implicitly enforced by Test 3, but let me make it explicit.

**Mutation test** (Test 12): In a copy of the layer, set W to a NON-TERNARY matrix (e.g. all 0.3s). Run forward. Verify that last_W_q_ is STILL ternary {-1, 0, +1} (proving round() actually quantized).

## Plan-level gotchas (reviewer checklist)

- **Ternary exactness:** `clamp(x, -1, 1)` for `|x| ≤ 1` followed by `std::round(x)` must return exactly ±1 or 0. In C++, `std::round(0.5)` returns 1.0 (round-half-away-from-zero), so a value at exactly 0.5 goes to +1. This is fine; the paper's `round()` is conventional. If a test ever fails because `W_q[o, j]` is e.g. 0.9999999999 instead of 1.0, we have a bug in the rounding. The W_q ∈ {-1, 0, +1} test asserts `value == -1.0 || value == 0.0 || value == 1.0` EXACTLY (with `==`).
- **STE mask `M[o, j] = 1 if |W[o, j]/scale_w[o]| ≤ 1 else 0`:** This is the "saturation gate". At the clamp boundary `|W/scale_w| = 1`, gradient passes through (gradient of `clamp` is 1 inside, 0 outside, with the boundary conventionally assigned to "inside"). The FD gradient check will catch a wrong sign or a missing mask.
- **Per-row scale_w convention:** the paper is per-OUTPUT unit (one scale per row of W). I'll cache `scale_w` as a (1, d_out) tensor matching Dense's bias shape convention. This makes `grad_scale_w[o] = Σ_n grad_Y[n, o] * Z[n, o]` a sum over N — exactly the same form as Dense's grad_bias.
- **TDD hygiene:** before declaring GREEN on each task, mutate a critical line (e.g. drop the `* scale_w[o]` factor, or set M=1 everywhere) and confirm the relevant test catches it.
- **FD input gradient degeneracy:** with default init (Xavier ~ 0.5), `scale_w` will be ~0.5, `W_hat` will be in [-1, 1], `W_q` will be ±1. The forward output is finite but smaller than standard Dense because of the quantization noise. To avoid degeneracy in FD: use **random non-uniform init** (NOT uniform — see TDD skill "uniform init masks row-vs-column confusion"). The current test plan uses `fill_det(seed, scale)` which produces non-uniform values — fine.
- **Skip dependency:** LoRA already in nn.h is a sibling — I add bitnet.h right after it (line 266). No umbrella-header issues expected.
