# HyenaDNA Implementation Plan

**Goal:** Add `HyenaDNAOperator` — the multi-head Hyena operator from Nguyen
et al., "HyenaDNA: Long-Range Genomic Sequence Modeling at Single Nucleotide
Resolution" (arXiv:2306.15794) §3.1 — plus the paper's two sequence-length /
adaptation utilities (`SequenceLengthWarmup`, `SoftPrompting`).

**Why this and not a new paper:** the 2026-10-03 queue note closed the Hyena
family except two gaps. `MultiHeadHyena` is not a separate paper (it is the same
§3.1 operator, already shipped single-head as `hyena.{h,cpp}`); `HyenaDNA` is a
genuinely separate section of arXiv:2306.15794 whose operator differs from the
shipped `HyenaOperator` in three structural ways (see "Differences" below).
Absence confirmed by content grep, not filename: `grep -ril 'hyenadna\|nucleotide\|soft_prompt\|seqlen' include/` → no hits outside
`hyena.{h,cpp}` / `striped_hyena.{h,cpp}`.

**Architecture:** `HyenaDNAFilter` (implicit filter MLP with
`ExponentialModulation` decay — **replaces** the shipped `HyenaFilter`'s
`h = exp(-delta*t)*h` decay with the paper's `deltas` linspace parameterization),
`HyenaDNAOperator` (multi-head, `num_heads` independent per-head convolutions
with a shared filter bank and per-channel `D` skip), `HyenaDNABlock` (pre-LN →
operator → residual → pre-LN → GELU FFN → residual), `HyenaDNAModel`.
Plus two paper utilities: `SequenceLengthWarmup` (§3.2, the staged 64→128→…
doubling schedule) and `SoftPrompting` (§3.3, Eq. 3.2, `concat[embed(x_p), θ]`).

**Tech Stack:** C++17, matches `hyena.{h,cpp}` / `striped_hyena.{h,cpp}` style.
Composes `Dense` / `LayerNorm` from the repo.

### The operator (arXiv:2306.15794 §3.1, Eq. 3.1)

> "Given an input `x ∈ R^L`, a Hyena operator can be defined as:
> `(x_1, x_2, v) ↦ H(x_1, x_2) v`  where
> `H(x_1, x_2) = D_{x_2} T_h D_{x_1}`.
> `T_h ∈ R^{L×L}` is the Toeplitz matrix constructed from a learnable long
> convolution filter produced as the output of a neural network,
> `(T_h)_{ij} = h_{i-j}`. … `D_{x_1}, D_{x_2} ∈ R^{L×L}` are constructed with
> `x_1, x_2` on the diagonals, and evaluated as element-wise gating. The
> projections are obtained by applying a dense linear layer and short
> convolution to the input sequence."

Multi-head (paper §3.1, "In the general case where the embedding dimension
`D > 1` … `D` independent Hyena operators are then applied to each dimension"):

```
u        = in_proj(x)                              (L, (order+1) * D)   [per head: (order+1) * head_dim]
uc       = short_depthwise_conv1d(u)               causal, kernel=short_filter_order (3)
split    = (x_1, ..., x_order, v)                  each (L, head_dim), per head
for o = order-1 down to 1:                         # "reversed(x[1:])"
    v  = v * x[o]                                  element-wise gate (D_x)
    v  = long_conv(v, k[o], bias[o]) + bias[o] * v  # T_h then per-channel skip
v        = v * x[0]                                 final gate
y        = out_proj(v)                              (L, D)
```

Per head `h` the filter bank supplies `order - 1` filters of length `L` plus
`order - 1` `D`-skip biases, all generated by ONE shared `HyenaDNAFilter`
whose output width is `head_dim * (order - 1)` — this is the **multi-head
difference**: the shipped `HyenaOperator` has a single filter of width `D` and
no head split at all.

### The implicit filter (official `HyenaFilter`)

- `PositionalEmbedding(emb_dim, seq_len)`: `t = linspace(0,1,seq_len)` normalized
  so `t_f = 1`; `bands = (emb_dim - 1) / 2`;
  `t_rescaled = linspace(0, seq_len-1, seq_len)`, `w = 2π·t_rescaled / seq_len`,
  `f = linspace(1e-4, bands-1, bands)`,
  `z = concat[t, exp(-i·f·w).real, exp(-i·f·w).imag]` → `(seq_len, emb_dim)`.
  **`emb_dim` must be odd and ≥ 3** (asserted in source; the repo's shipped
  filter uses `emb_dim=3` default).
- `Sin(dim, w)`: learnable per-channel `freq = w · 1` of shape `(1, dim)`,
  `forward(x) = sin(freq · x)`. `freq` is a **learnable parameter** — the
  shipped `HyenaFilter` already does this (`sin_freq`).
- Implicit MLP: `Linear(emb_dim, order) → Sin → [Linear(order,order) → Sin] ×
  num_inner_mlps → Linear(order, d_model, bias=false)`.
- `ExponentialModulation`: `deltas = linspace(log(target)/slow_decay_pct,
  log(target)/fast_decay_pct, d_model)`, `forward(t, h) = h * (exp(-t·|deltas|) + shift)`.
  Defaults `fast_decay_pct=0.3, slow_decay_pct=1.5, target=1e-2, shift=0`.
  In the source `deltas` is registered with `lr=0.0` (frozen by default) — we
  make it a normal learnable tensor and document the divergence.
- `filter(L)` returns `h = modulation(t, implicit_mlp(z))`, optionally
  L1-normalized (HyenaDNA does **not** set `normalized`).

### Sequence-length warm-up (§3.2)

> "Our sequence length schedule starts at `L_1 = 64`, then doubles the window
> at each stage while keeping the global batch size constant."

Stage `i` runs for `epoch_scale * 2^i` epochs, sequence length `64 * 2^i`.
`epoch_scale` is the per-stage epoch count. This is a **training-loop**
utility, not a layer.

### Soft prompting (§3.3, Eq. 3.2)

> "we prepend `N ≤ L − T` trainable parameters `θ` of dimension `D` after the
> embedding step: `x ← concat[embed(x_p), θ]`, `x ∈ R^{L×(T+N)}`."

`θ ∈ R^{N×D}` is the only thing optimized; all model parameters stay fixed.
Note the paper writes `R^{L×(T+N)}` but the concat is on the **sequence**
axis, so the result is `(T + N) × D` in the repo's row-major convention.

## Differences from the shipped `HyenaOperator` (why not just reuse it)

| Aspect | Shipped `HyenaOperator` | `HyenaDNAOperator` |
|---|---|---|
| Heads | none (single `D`-wide) | `num_heads`, per-head `head_dim` filters |
| Filter output width | `D` | `head_dim * (order - 1)` filters + `(order-1)·head_dim` biases |
| Skip connection | `D_skip` returned by filter, added in-conv | per-channel learnable `bias` param on the filter |
| Modulation decay | `h = exp(-delta * t) * h`, `deltas` is `(1, D)` | `h = (exp(-t·|deltas|) + shift) * h`, `deltas` linspace over `log(target)/pct` |
| `D` skip applied | inside `long_conv` | after the long conv, `y = conv + bias*v` |
| `num_blocks` / `inner_factor` | absent | present in the reference; **omitted in v1** (YAGNI) |

Reusing the shipped filter would import all of `Deltas`' different
parameterization, so this is a genuinely separate implementation, not a wrapper.

## Public API contract (v1)

Files: `include/nn/layers/architectures/hyena_dna.{h,cpp}`,
registered in `include/nn/nn.h` (after `striped_hyena.h`, line 238) and given a
`build/test_hyena_dna` target plus `run_tests` lines in the `Makefile`.

**Conventions:** sequences are `(L, d_model)` row-major `Tensor`s. No batching
— matches the shipped `HyenaOperator`'s per-token mode and every other
architecture in the repo. `order >= 2` enforced (official source asserts
`order >= 2`).

```cpp
// ---- HyenaDNAFilter: implicit long-conv filter bank ------------------------
class HyenaDNAFilter {
public:
    HyenaDNAFilter(size_t d_model, size_t l_max, size_t filter_order = 16,
                   size_t emb_dim = 3, size_t num_inner = 1,
                   size_t short_filter_order_unused = 0);
    // Returns h of shape (L, d_model). Caches for backward.
    Tensor filter(size_t L);
    // grad_h: (L, d_model). Returns nothing; accumulates into grad_*.
    void backward(const Tensor& grad_h);
    void zero_grad();
    std::vector<Tensor*> parameters();
    std::vector<Tensor*> gradients();
    size_t d_model() const; size_t l_max() const; size_t filter_order() const;
    size_t emb_dim() const;  size_t num_inner() const;
    Tensor last_pos_emb() const;   // (L, emb_dim) cached z  [test seam]
};
```

Parameters: `mlp_in_W (P, emb_dim)`, `mlp_in_b (1, P)`, `sin_freq (1, P)`,
`mlp_W[i] (P, P)` × `num_inner`, `mlp_b[i] (1, P)` × `num_inner`,
`mlp_out_W (D_f, P)` [no bias — official source uses `bias=False` on the final
layer], `deltas (1, D_f)`, `bias (1, D_f)`. `D_f = d_model` here.

```cpp
// ---- HyenaDNAOperator: multi-head Hyena operator (Eq. 3.1) -----------------
class HyenaDNAOperator : public Layer {
public:
    HyenaDNAOperator(size_t d_model, size_t l_max, size_t num_heads = 1,
                     size_t order = 2, size_t filter_order = 16,
                     size_t short_filter_order = 3);
    Tensor forward(const Tensor& input) override;     // (L, D) -> (L, D)
    Tensor backward(const Tensor& grad_output, double lr) override;
    void update_weights(double lr) override;
    Tensor get_weights() const override;  Tensor get_gradients() const override;
    std::vector<Tensor*> parameters() override; std::vector<Tensor*> gradients() override;
    void zero_grad() override;
    std::string name() const override { return "HyenaDNAOperator"; }
    size_t d_model() const;  size_t l_max() const;  size_t num_heads() const;
    size_t head_dim() const; size_t order() const;   size_t filter_order() const;
    size_t short_filter_order() const;
};
```

Constructor throws on: `d_model=0`, `l_max=0`, `num_heads=0`,
`d_model % num_heads != 0`, `order < 2`, `short_filter_order=0`,
`filter_order=0`.

Per-head layout: `in_proj` is `Dense(D, (order+1)·D)`, applied per token; after
`short_conv` the `(L, (order+1)·D)` tensor is reinterpreted as
`(L, num_heads, (order+1)·head_dim)` with column index
`h*(order+1)*head_dim + o*head_dim + c`.

```cpp
// ---- §3.2 sequence-length warm-up (training-loop utility, NOT a Layer) ------
class SequenceLengthWarmup {
public:
    // paper: L_1 = start_len (64), doubles each stage
    SequenceLengthWarmup(size_t start_len = 64, size_t num_stages = 8,
                         size_t epoch_scale = 1);
    size_t num_stages() const;
    size_t seq_len_for_epoch(size_t epoch) const;    // piecewise-constant
    size_t stage_for_epoch(size_t epoch) const;
    size_t total_epochs() const;
    size_t max_seq_len() const;
};

// ---- §3.3 soft prompting (Eq. 3.2) -----------------------------------------
class SoftPrompting : public Layer {
public:
    SoftPrompting(size_t prompt_len, size_t d_model, bool at_front = true);
    Tensor forward(const Tensor& embedded) override;  // (T, D) -> (T+N, D)
    Tensor backward(const Tensor& grad_output, double lr) override;
    void update_weights(double lr) override;
    std::vector<Tensor*> parameters() override;  std::vector<Tensor*> gradients() override;
    void zero_grad() override;
    size_t prompt_len() const;  size_t d_model() const;  bool at_front() const;
    Tensor& prompt() { return prompt_; }   // trainable theta, (N, D)
};
```

`SoftPrompting::forward` **validates `T + N <= l_max` is the caller's
responsibility**; it throws only on a `d_model` mismatch and on
`prompt_len=0` / `d_model=0` at construction. `backward` returns the gradient
w.r.t. `embedded` (zeros) and accumulates the prompt's gradient by scatter —
this is the correct signature for a `Layer` and is exactly why `T + N` is the
caller's arithmetical responsibility.

## Test suite (target ≥ 45 checks)

| # | Test | Key assertions |
|---|---|---|
| 1 | Constructor validation | 7 throws + valid + 5 accessors per class |
| 2 | Positional embedding | `z = [t, cos(2πft_resc/L), sin(…)]`, hand-derived `emb_dim=5` |
| 3 | Filter closed forms | `Sin` freq, `deltas` endpoints `log(1e-2)/1.5`…`log(1e-2)/0.3`, decay applied, no final-layer bias |
| 4 | Filter FD | 5 param tensors, random init |
| 5 | Operator forward | shape/finite/nonzero, per-head independence, `L=1` |
| 6 | Operator FD | input + 5 param tensors |
| 7 | Block | shape, `ffn_mult=0`, FD input |
| 8 | Model | shape, FD input, training reduces loss |
| 9 | SequenceLengthWarmup | `64, 128, 256…`, boundaries, totals |
| 10 | SoftPrompting | shape, both concat orders, FD prompt grad, zero embedded-grad |

**Anti-vacuity requirements (from the TDD skill):**
- Random **non-uniform** init everywhere (`Tensor::random(0.3)`), never
  `for i,j: w[i][j]=0.1` — a uniform init makes `Σ_k W[k,j] == Σ_k W[j,k]`,
  so a row/column transpose in the matmul backward passes vacuously.
- `denom = max(|ana|, |num|); if (denom < 1e-9) denom = 1.0` — avoids `rel_err ≈ 1`
  when both sides sit at the double-precision noise floor.
- **Half-scale vacuity:** FD-vs-analytical is *structurally blind* to
  constant-factor bugs. So T13 must include a **hand-derived magnitude test**:
  a closed-form `emb_dim=5, filter_order=1, num_inner=0, L=1` filter value
  computed by hand and asserted against a specific number, not against another
  implementation of the same formula.
- **Single-iteration vacuity:** `order=2` gives exactly ONE long-conv iteration,
  so a `+=` vs `=` mutation in the operator loop passes vacuously. T6/T8 must
  run at **`order=3`** (two iterations) for at least one FD case, and the
  mutation test in T13 must use that config.

## Decisions

| # | Decision | Rationale |
|---|---|---|
| D1 | New `HyenaDNAFilter` class, do **not** extend the shipped `HyenaFilter` | Different `ExponentialModulation` parameterization, different output width, different `D`-skip placement. Wrapping would import the old design's choices. |
| D2 | O(L²) naive long conv, not FFT | Same rationale as the shipped `hyena.cpp` header comment: keeps the gradient check tractable at small L and is a clean drop-in upgrade. |
| D3 | No batching; `(L, D)` per-token sequences | Matches every other architecture in the repo and the shipped `HyenaOperator`'s per-token mode. |
| D4 | `deltas` is a normal learnable tensor | The official source registers it with `lr=0.0` (frozen). Making it learnable is the more useful default for a library; documented as a deliberate divergence. |
| D5 | `num_blocks` / `inner_factor` omitted | YAGNI. The paper does not use them for HyenaDNA. |
| D6 | Utilities are plain classes, not `Layer` subclasses | `SequenceLengthWarmup` is a training-loop concern with no tensors. `SoftPrompting` IS a `Layer` because it has a trainable parameter. |
