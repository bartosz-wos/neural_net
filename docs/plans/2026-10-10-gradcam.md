# Grad-CAM Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Ship Grad-CAM (Selvaraju et al., arXiv:1610.02391) — the sixth and final
interpretability method family — as `include/nn/interpretability/gradcam.{h,cpp}`
plus `tests/test_gradcam.cpp`, with zero changes to the base `Layer` / `Model`.

**Architecture:** Grad-CAM needs `dL/d(input)` of an **intermediate** layer. The
expansion queue predicted this requires a repo-wide `cache_input_grad_` virtual
on the base `Layer` touching ~250 layers. **That prediction is wrong, and the
cheapest correct design proves it:** `Model::layers` is a *public*
`std::vector<std::unique_ptr<Layer>>`, and `Layer::backward` **returns**
`dL/d(input)`. So a caller can run the forward pass manually, snapshot the
activation of the target layer, seed the output with a one-hot on `target`, and
walk `model.layers` in reverse calling `layer->backward(...)` — capturing the
tensor returned by the call *immediately after* the target layer. That tensor is
the Grad-CAM activation gradient. No hook, no base-class change, no regression
risk to 250 layers.

**Tech Stack:** C++17, hand-rolled 2-D `Tensor` (real, row-major), existing
`Model`/`Layer`/`Conv2D`. Tests use the repo's `check`/`check_close`/`check_throws`
idiom and centred finite differences.

**Conv2D output layout** (verified by reading `conv_layer.cpp:143-151`, `:67-83`):
output is `(N, out_channels * H_out * W_out)` with column
`c * (H_out*W_out) + i*W_out + j` — channel-major, then row-major within the
channel. `im2col` uses the same `col_idx = n*H_out*W_out + i_out*W_out + j_out`
ordering, so a `(C, H_out, W_out)` view is exact and needs no transposition.

## Decisions

| # | Decision | Rationale |
|---|---|---|
| D1 | No base-`Layer` hook; walk `model.layers` manually | `layers` is public; `backward` returns dL/d(input). Cheapest correct design, zero blast radius. |
| D2 | Batch dimension must be **1** | GAP weights are per-example and the repo's `Tensor` is one flat 2-D buffer; a batch of N would need N separate CAMs. Enforce with a throw. |
| D3 | Seed the output with a one-hot on `target` | Same idiom as `input_gradient` (`attribution.cpp:19-26`). Attributes the **logit**, never a softmax probability — same reasoning as the IG entry. |
| D4 | ReLU applied ONCE at the end | Eq. 2 / `grad_cam.py:241-242`. Applying it per-channel before the weighted sum is a plausible-looking bug that changes every value. |
| D5 | Zero parameter grads before *and* after | `Dense::backward` accumulates into `grad_weights`; an attribution pass must not perturb training state. Matches `input_gradient`. |
| D6 | Ship `upsample_bilinear` as a free function | The paper's Fig. 1 upsamples the 14×14 CAM to the input size. No generic helper exists in the repo (`grep -rn upsample include/nn/layers/` → only a Consistency-specific one). |

## Vacuity traps this suite must avoid

1. **GAP over the wrong axis.** The repo flattens `(N, C·H·W)`; summing over the
   whole row instead of over the `H·W` block gives a *different* number, not the
   same one up to a constant. Test 3 pins the exact hand-computed value.
2. **ReLU before weighting.** Test 6 pins `ReLU(Σ α A)`, not `Σ α ReLU(A)`.
3. **A dead gradient.** A CAM is all zeros if the seeded backward never reaches
   the target layer. Test 2 asserts a nonzero sum before anything else.
4. **Degenerate activations.** If every activation is zero (ReLU'd dead), the
   CAM is zero *correctly* and the test would pass vacuously. Use a fixture with
   mixed-sign activations.
