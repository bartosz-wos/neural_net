# GATv2 — Improved Graph Attention Network — Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Add `GATv2Layer` and `GATv2Model` in `include/nn/layers/attention/gatv2.{h,cpp}` — the Brody, Alon, Yahav 2022 fix for GAT's "static" attention problem. Reorders GAT's attention from `α_ij = softmax_j(a^T [W·h_i ‖ W·h_j])` to `α_ij = softmax_j(a^T W [h_i ‖ h_j])`. Strictly more expressive while keeping the same parameter count.

**Architecture:** Standalone graph-attention layer + a small stackable model. Reuses the GAT v1 conventions (row-softmax over adjacency-masked scores, LeakyReLU on the output, multi-head concat-or-average, `(N, in_features)` flat-tensor input + `(N, N)` adjacency input via `forward_with_adj`, `Tensor::forward()` returning the cached output). Cached forward state for the full hand-derived backward chain.

**Tech Stack:** Tensor (existing), `std::mt19937` (existing init convention from GAT v1), no new dependencies.

**Reference:**
- Brody, Alon, Yahav 2022, "How Attentive are Graph Attention Networks?", https://arxiv.org/abs/2105.14491.
- Sibling `GATLayer` in `include/nn/layers/attention/gat.{h,cpp}` — copy the file shape, parameter storage, cache pattern, backward convention. The math change is *local* to the per-head score computation; everything else (multi-head combine, input projection backward through Wh, softmax backward, LeakyReLU backward, masking) is identical to GAT v1.
- Reference implementation: https://github.com/tech-srl/how_attentive_are_gats (Brody et al. official PyTorch). Verified by content grep that the per-head score is `e_ij = a^T · (W · [h_i ‖ h_j])` — i.e. concat THEN matmul (the "modified" form), not the GAT v1 "matmul each THEN concat" form.

**Math (paper §2.1):**
```
Wh_i = W · h_i                                           ∈ R^{F'}
s_ij = W · [h_i ‖ h_j]                                   ∈ R^{F'}    (concat inputs FIRST, then one matmul)
e_ij = LeakyReLU(a^T · s_ij)                             ∈ R
α_ij = softmax_j(e_ij) over j ∈ N(i) ∪ {i}              ∈ R
h'_i  = LeakyReLU(sum_j α_ij · Wh_j)                      ∈ R^{F'}
```

Per-head parameters: `W ∈ R^{F' × in_features}` and `a ∈ R^{F' × 1}` (note `a` is now `F'`-dim, NOT `2F'`-dim — that's the v1 trick that caused the static-attention problem; in v2 the concat is in input-space, so `a` is one head's worth).

Backward chain (identical to GAT v1 except for `grad_dot → grad_W`/`grad_a` and `grad_Wh` paths):
1. `grad_head_out` from `grad_output` slice (concat or average).
2. LeakyReLU' on cached `last_head_pre_`.
3. Direct: `grad_Wh_direct[j, k] = Σ_i α_ij · grad_head_out[i, k]`, `grad_alpha_direct[i, j] = Σ_k grad_head_out[i, k] · Wh[j, k]`.
4. Softmax backward on row α: `grad_e[i, j] = α[i, j] · (grad_alpha_direct[i, j] − Σ_k α[i, k] · grad_alpha_direct[i, k])`.
5. LeakyReLU' on cached `last_e_`: `grad_dot[i, j] = grad_e[i, j] · leaku_deriv`.
6. **NEW (v2 only):** the score is `s_ij = W · [h_i ‖ h_j]`, so `grad_W` and `grad_a` decompose differently than v1:
   - `grad_a[k, 0] = Σ_{i, j} grad_dot[i, j] · s_ij[k] / F' · 1{k}` — actually `grad_a[k] = Σ_{i,j} grad_dot[i, j] · s_ij[k]` summed over all (i, j), masked by adjacency.
   - `grad_W[k, in] = Σ_{i, j} grad_dot[i, j] · a[k] · x_input(i, j, in)` where `x_input(i, j, in)` is `input[i, in]` for the first half (k < F') and `input[j, in]` for the second half. This gives a single `grad_W` accumulator over both halves.
   - We can split this into the "i half" and "j half" contributions (analogous to GAT v1's split) and sum them. **But** `grad_W` in v2 receives contributions from BOTH halves via `s_ij = W · x_concat` — the matmul `W · x_concat` has `x_concat = [h_i ‖ h_j]` and `W` is `(F', 2*in)`. So `grad_W[k, c]` for `c < in` accumulates from the `i` side, and `c >= in` accumulates from the `j` side.
   - In GAT v1's "split W" view, `grad_Wh_indirect[i, k] += Σ_j grad_dot[i, j] · a[k]` (i side, half-W) and `grad_Wh_indirect[j, k] += Σ_i grad_dot[i, j] · a[F'+k]` (j side, OTHER half-W). In GAT v2, `grad_Wh_indirect[i, k] += Σ_j grad_dot[i, j] · a[k]` (i side, k-th row of W) AND `grad_Wh_indirect[j, k] += Σ_i grad_dot[i, j] · a[k]` (j side, SAME k-th row of W — because v2 has only ONE `W`, not two half-Ws). Then `grad_W[k, c] = Σ_n grad_Wh[n, k] · x_input_at_half(n, c)` where the half is determined by `c < in` (i-side) or `c >= in` (j-side).
   - To keep the math close to v1, I'll factor `grad_Wh_indirect_total[i, k]` = (sum over j for the i-side) + (sum over i' for the j-side where i' is the current query). Then in the final `grad_W = grad_Wh_indirect_total.T @ input_with_self_loop_per_half` step.
   - **The simplest correct formulation**: cache `Wh_j_for_all_j[j, k] = W[k] · input[j]` (same as v1) AND `Wh_i = W[h*0..F'[, :] · input` (first F' columns of W). Then `grad_W[:, 0:in]` = sum over all (i, j) of `grad_dot[i, j] · a · input[i]` and `grad_W[:, in:2in]` = sum over all (i, j) of `grad_dot[i, j] · a · input[j]`. Equivalently:
     - `grad_W_indirect[k, c<in] = Σ_i (Σ_j grad_dot[i, j]) · a[k] · input[i, c]` — i-side
     - `grad_W_indirect[k, c>=in] = Σ_j (Σ_i grad_dot[i, j]) · a[k] · input[j, c-in]` — j-side
     - where the inner sum `Σ_j grad_dot[i, j]` (or `Σ_i`) depends on which side.
     - And the **direct path** `grad_W_direct[k, c] = Σ_n grad_Wh_direct[n, k] · input[n, c_for_half]` — same form as v1 except v1 has two half-Ws while v2 has one W used twice.
7. `grad_input` via `grad_Wh @ W_first_in` (i-side) AND `grad_Wh @ W_second_in` (j-side), summed. In GAT v1, this was `grad_Wh[i, j] * W[j, k]` summed — the SAME form here because `Wh = W · x` where `W[k, c]` projects `x[c]` to `Wh[k]`. The `grad_Wh → grad_input` chain goes:
   - For `c < in` (the i-half of any hypothetical concat input): `grad_input[i, c] += Σ_k grad_Wh[i, k] · W[k, c]` (the i-side contribution to `grad_input[i]`).
   - For the j-half, the contribution to `grad_input[j, c] += Σ_k grad_Wh[i, k] · W[k, in+c]` summed over all queries i that attended to j. Note: in GAT v1 this was already handled by the "grad_Wh_indirect[j, k] += Σ_i grad_dot(i, j) · a[F'+k]" path accumulating into `grad_Wh[j, k]`, then `grad_input[j, c] += grad_Wh[j, k] · W[F'+k, c]`. So the SAME formulation works: v1 just happens to have split `W` into two `head_dim × in` tensors `[W_i; W_j]` so `W_i` is the first `head_dim` rows and `W_j` is the last `head_dim` rows of the conceptual `W ∈ R^{2F' × in}`. In v2, the conceptual `W ∈ R^{F' × 2in}` has the first `in` columns as the i-side and the last `in` columns as the j-side. **So:** in v2, the i-half of `W` is `W[:, 0:in]` (the same `W` projected against `input[i]` for the i-side) and the j-half is `W[:, in:2in]` (the same `W` projected against `input[j]` for the j-side). The backward is therefore structurally identical to v1, with these substitutions:
     - `W[k, c]` for i-half: `W[k, c]` (k in [0, F'), c in [0, in))
     - `W[k, c]` for j-half: `W[k, in + c]` (k in [0, F'), c in [0, in))
     - `a` for i-half: `a[k]` (v2 only has ONE `a`, used for both halves)
     - `a` for j-half: `a[k]` (same)
     - The `grad_Wh_indirect` accumulator: `grad_Wh_indirect[i, k] += Σ_j grad_dot[i, j] · a[k]` (i-side) AND `grad_Wh_indirect[j, k] += Σ_i grad_dot[i, j] · a[k]` (j-side) — both halves use the SAME `a[k]`.

   So the **grad_W chain** is:
     - For i-side contribution to `grad_W[k, c<in]`: `Σ_i (Σ_j grad_dot[i, j]) · a[k] · input[i, c] + Σ_i grad_Wh_direct[i, k] · input[i, c]`.
     - For j-side contribution to `grad_W[k, in+c]`: `Σ_j (Σ_i grad_dot[i, j]) · a[k] · input[j, c] + Σ_j grad_Wh_direct[j, k] · input[j, c]` (same form, summed over rows of grad_Wh_direct).
     - Equivalently: for each row k of W, `grad_W[k, 0:in] = (grad_Wh_direct.T + grad_Wh_indirect_v2.T)[k, 0:in] @ input` where `grad_Wh_indirect_v2[i, k] = Σ_j grad_dot[i, j] · a[k]` plus the j-half-accumulated-into-grad_Wh_indirect_v2[j, k] = Σ_i grad_dot[i, j] · a[k]` (both halves added together), and `grad_W[k, in:2in]` = same `grad_Wh_total.T @ input` (treating each half as `W` against its respective input side).
   - This is exactly the v1 backward with `a[F'+k] → a[k]` for the j-half AND `W[F'+k, :] → W[k, :]`.

OK, on careful re-derivation, the cleanest implementation is to keep the v1 backward STRUCTURE but substitute:
   - `W_v2 ∈ R^{F' × in}` (single per head, F' × in — half the params of v1's `W ∈ R^{2F' × in}`).
   - `a_v2 ∈ R^{F' × 1}` (single per head, F' × 1 — half the params of v1's `a ∈ R^{2F' × 1}`).
   - For `Wh`: in v1, `Wh_i = W_v1 · h_i` where `W_v1 ∈ R^{2F' × in}` and `Wh_i ∈ R^{2F'}`; in v2, `Wh_i = W_v2 · h_i` where `W_v2 ∈ R^{F' × in}` and `Wh_i ∈ R^{F'}`. So the OUTPUT of `Wh` in v2 is `F'`-dimensional, same as v1's per-head dimension. The "two halves of W in v1" pattern collapses in v2 to "use the same W twice" — once for the i-side and once for the j-side, which is exactly what makes v2 strictly more expressive (the same learned projection is applied to both h_i and h_j).

The **forward** of v2 is therefore:
```
Wh = input @ W.T   (N, F')
For each (i, j):
  s_ij = [Wh[i] || Wh[j]]    (concatenation, 2F' elements)
  score = a.T @ s_ij         (F' × 2F' @ 2F' = scalar)
  e_ij = LeakyReLU(score)
α = softmax_j(e) over masked rows
head_pre[i] = sum_j α[i, j] · Wh[j]
head_out[i] = LeakyReLU(head_pre[i])
```

The **backward** of v2 is:
```
grad_head_pre = LeakyReLU'(head_pre) * grad_output[head h slice]
grad_Wh_direct[j] = sum_i α[i,j] * grad_head_pre[i]
grad_alpha_direct[i, j] = sum_k grad_head_pre[i, k] * Wh[j, k]
grad_e[i, j] = α[i,j] * (grad_alpha_direct[i,j] - sum_k α[i,k] * grad_alpha_direct[i,k])
grad_dot[i, j] = LeakyReLU'(e[i,j]) * grad_e[i, j]

# Indirect contributions to grad_Wh via the score path
# s_ij = [Wh[i] || Wh[j]], score = a.T @ s_ij
# grad_s_ij[k] = grad_dot[i,j] * a[k]    (k in [0, F'))
# d(Wh[i])[k] += grad_s_ij[k] for the i-half (k in [0, F') → grad_Wh[i, k])
# d(Wh[j])[k] += grad_s_ij[k] for the j-half (k in [0, F') → grad_Wh[j, k], SAME k)
# Both halves use the SAME a[k] (this is the v2 difference from v1).

grad_Wh_indirect[i, k] = (sum_j grad_dot[i, j]) * a[k]    # i-half accumulator
grad_Wh_indirect[j, k] += (sum_i grad_dot[i, j]) * a[k]   # j-half accumulator (same a[k])

grad_Wh_total = grad_Wh_direct + grad_Wh_indirect

# grad_W chain:
# In v2, W ∈ R^{F' × in} is a SINGLE matrix. The i-half of grad_W corresponds to the
# contribution from Wh[i]'s i-side input, the j-half to Wh[j]'s j-side input.
# But because Wh = X @ W.T (single W), grad_W[k, c] = sum_n grad_Wh_total[n, k] * X[n, c]
# This is the SAME formula for both halves of W — there are no separate half-Ws in v2.
# grad_W = grad_Wh_total.T @ input   (F' × in)

# grad_a chain:
# a[k] contributes via s_ij[k] which feeds grad_s_ij[k] which is grad_dot[i, j] * a[k]
# Wait — that's circular. Let me redo:
# score = a^T @ s_ij = sum_k a[k] * s_ij[k]
# grad_a[k] = sum_{i,j adj} grad_dot[i,j] * s_ij[k]
# where s_ij[k] for k in [0, F') is Wh[i, k] (i-half) and for k in [F', 2F') is Wh[j, k-F'] (j-half).
# But we don't have an explicit s_ij cache; we reconstruct it as [Wh[i] || Wh[j]].
# We do have Wh cached. So:
# grad_a[k< F'] = sum_{i,j adj} grad_dot[i, j] * Wh[i, k]
# grad_a[k>=F'] = sum_{i,j adj} grad_dot[i, j] * Wh[j, k-F']

# grad_input chain:
# Wh[i] = W @ input[i]   (Wh[i, k] = sum_c W[k, c] * input[i, c])
# grad_input[i, c] += sum_k grad_Wh_total[i, k] * W[k, c]    (i-side path)
# BUT in v2, the j-side path also contributes to grad_input[j]: Wh[j] depends on input[j]
# in the SAME way, so grad_input[j, c] += sum_k grad_Wh_total[j, k] * W[k, c] (j-side path).
# This is exactly what grad_Wh_indirect[j, k] += (sum_i grad_dot[i, j]) * a[k] accumulates.
# So the simple formula grad_input = grad_Wh_total @ W (matmul: (N, F') @ (F', in) = (N, in))
# captures BOTH the i-side and j-side contributions in v2, because grad_Wh_total already
# includes both halves via the indirect accumulator.
```

**Verification of the formula equivalence:** the v1 backward has `grad_input[i] += grad_Wh[i, k] * W_v1[k, c]` summed over k, where `W_v1` is conceptually `2F' × in` (split into W_first and W_second). The v2 backward has `grad_input[i] += grad_Wh_total[i, k] * W_v2[k, c]` summed over k, where `W_v2` is `F' × in` and `grad_Wh_total` is the combined direct + indirect accumulator. **The formula is structurally identical; the only changes are the sizes of W (F' × in instead of 2F' × in) and a (F' × 1 instead of 2F' × 1), and the j-half of the indirect accumulator uses the SAME a[k] instead of a[F'+k].**

This means: **the v2 implementation can be done by adapting the v1 code with two size changes and one "use same `a[k]` for both halves" change.** No structural rewrites needed.

**Why this is more expressive than v1 (Brody et al. 2022, Theorem 1):** GAT v1's score is `a^T [Wh_i ‖ Wh_j]`, which can be written as `a_1^T Wh_i + a_2^T Wh_j` — the SUM of two independently-learned linear functions. This is provably rank-limited in its attention pattern (the score difference `e_ij - e_ik = a_2^T (Wh_j - Wh_k)` is independent of `i`, so the ranking of neighbors is the same for every query — "static" attention). GAT v2's score is `a^T W [h_i ‖ h_j] = a^T (W · h_i ‖ W · h_j)` — wait, that's not right. Let me re-read the paper.

Brody et al. 2022 §2.1 says: "In GATv2 we modify the attention mechanism to compute `e_ij = a^T · (W · [h_i ‖ h_j])`. [...] This modification has the same number of parameters and strictly improves the expressive power." The `W` is applied to the concatenation (2F' input → F' output), then `a` projects the F'-dim result to a scalar. So:

```
score = a^T · (W · concat(h_i, h_j))
      = a^T · s_ij,    where s_ij = W · [h_i ‖ h_j] ∈ R^{F'}
```

The score is a sum over k of `a[k] · (Σ_{c<in} W[k, c] · h_i[c] + Σ_{c>=in} W[k, c] · h_j[c])`. So the score IS still a sum of two halves (one for h_i and one for h_j), BUT the SAME `W[k, c]` appears in both halves when `c<in` vs `c>=in` (because `W` is shared). The key v2 property: the linear combination of `h_i`'s features that determines attention weight now depends on `h_j` (via the cross-coupling in `W`'s columns) and vice versa — i.e., `a^T W` is a single F'-dim vector that scores BOTH halves together, and the columns of `W` interact between the i-side and j-side during learning.

Actually, the cleaner way to see it: v1 computes `α_ij ∝ exp(a_1^T Wh_i + a_2^T Wh_j)` — attention is the sum of two INDEPENDENT contributions. v2 computes `α_ij ∝ exp(a^T W [h_i ‖ h_j]) = exp(a^T W_1 h_i + a^T W_2 h_j)` where `W_1` and `W_2` are the first and second halves of W's columns — and crucially `a^T W_1` is now coupled with `a^T W_2` through the SHARED projection `W`. So the linear combination of `h_i`'s features that determines attention is `a^T W_1`, which IS coupled to the linear combination of `h_j`'s features `a^T W_2` through learning.

OK enough theory — the implementation is the simple size-substitution adaptation of v1.

## Notes / Risks

- **The "two halves of v2 use the same a[k]"** is the SUBTLE implementation detail that distinguishes v2 from v1. A naive copy-paste of v1's `grad_Wh_indirect[j, k] += sum_i grad_dot[i, j] * a[F'+k]` would silently produce a v1 implementation, not v2. The mutation test (16) catches this.
- **Concat-then-dot vs split-then-dot**: the forward must be `s_ij = [Wh_i ‖ Wh_j]; score = a^T @ s_ij`, NOT `score = a_1^T @ Wh_i + a_2^T @ Wh_j`. The latter would be a v1 implementation in disguise (with `a_1` and `a_2` being the two halves of `a`). The forward cache must include the concat (or equivalently, a reconstructed `s_ij` shape — but v2 only needs `Wh` and `a` cached; the concat is implicit in the index bookkeeping).
- **Edge cases**: N=1 (single node, only self-attention, alpha = 1.0 always), N=0 (shouldn't be supported), in_features = 1 (smallest valid input).
