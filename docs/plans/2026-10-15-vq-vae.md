# VQ-VAE Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Ship the Vector Quantized Variational Autoencoder (van den Oord et al.,
arXiv:1711.00937) as `layers/generative/vq_vae.{h,cpp}` with a TDD test suite
whose every numeric expectation is transcribed from a float64 numpy oracle.

**Architecture:** Two layers. `VectorQuantizer` is the loss-based quantizer of
paper Eq. (3) — the codebook is a *parameter* updated by the dictionary term.
`VectorQuantizerEMA` is the moving-average variant, in which the codebook is
*not* a gradient-updated parameter at all but is overwritten each step by the
EMA statistics. A third layer `VQVAE` composes them with Dense encoder/decoder
so the whole model is a drop-in `Layer`. Every numerical core is a **free
function** over `Tensor`s, so the whole quantizer is testable with no
`Model`, no optimizer and no encoder.

**Tech Stack:** C++17, the repo's own `Tensor`/`Layer`/`Dense`, g++ with the
project's real `-O2 -march=native -Wall -Wextra`. Oracle: numpy 2.5.4 float64
in `~/.hermes/cache/scratch/venv`.

### The one sentence that matters most

> **The two VQ terms of Eq. (3) are numerically identical scalars and differ
> only in which operand carries the stop-gradient.**

`‖sg[z_e] − e‖²` and `β‖z_e − sg[e]‖²` are the *same number*; the dictionary
term is a function of the codebook alone and the commitment term is a function
of `z_e` alone. This was **not** understood correctly on the first pass — see
Task 3, which records the FD harness bug this caused.

## Semantics pinned (each is a natural mistake; each gets a named test)

- **D1 — the dictionary term is UNWEIGHTED and the commitment term carries β.**
  Sonnet line 102: `loss = q_latent_loss + commitment_cost * e_latent_loss`,
  where `e_latent_loss = mean((sg[quantized] − inputs)²)` (the **dictionary**
  term, gradient to `e`) and `q_latent_loss = mean((quantized − sg[inputs])²)`
  (the **commitment** base, gradient to `z_e`). Multiplying the wrong one by
  β is the single most common error in a reimplementation. Pinned by an
  explicit assertion that `grad_z_e` carries exactly a factor `β`.
- **D2 — the mean is over ALL M·D scalar elements**, not over rows.
  `reduce_mean` over the whole tensor. A per-row mean would make the gradient
  depend on M in a way the reference does not.
- **D3 — the codebook is stored `(D, K)`, i.e. COLUMN k IS embedding `e_k`.**
  This matches Sonnet's `self._w` of shape `[embedding_dim, num_embeddings]`
  (line 63) and makes `sum(w**2, 0)` the per-codebook-vector L2 norm directly.
  Transposing it is the natural mistake. Pinned by asserting the row-norms.
- **D4 — nearest neighbour is `argmax(−distance)`, and the tie-break is
  first-wins.** `argmin` over squared distances. With `e_2` and `e_3` made
  bit-identical and `z` exactly on that vector, both distances are
  **bit-identical** and the oracle picks index **2**. No tolerance-based test
  can see a tie-break, so the fixture must contain an exact tie.
- **D5 — the straight-through estimator's VALUE is `z_q`, not `z_e`.**
  Sonnet line 104: `quantized = inputs + stop_gradient(quantized − inputs)`.
  The value is exactly `z_q` (bit-identical, asserted); only the *gradient* is
  the identity. An implementation that returns `z_e` from `forward()` is a
  **broken quantizer** — it has quantized nothing — and no loss test catches
  it, which is why this is a headline assertion.
- **D6 — under EMA the dictionary term is DROPPED from the loss entirely.**
  Sonnet line 240: `loss = commitment_cost * e_latent_loss`, with no
  `q_latent_loss`. The codebook is replaced by `assign`, not by a gradient.
- **D7 — the EMA Laplace smoothing is `(n_k + ε)/(n + Kε) · n`, and it is what
  makes the update non-trivial.** Sonnet lines 231–233. Dividing by `n_k`
  directly gives a visibly different answer (`0.5500…` vs the oracle's
  `0.55036630036630052`).
- **D8 — a codebook entry that is never assigned collapses to EXACTLY ZERO
  under EMA, it does not keep its initial value.** With `ε = 1e-5`, an
  unassigned code gets `n_k = ε`, so `ema_w[:,k] / n_k = 0/ε = 0`. This is
  observable and surprising, and it is a real property of the reference.
- **D9 — perplexity is never exactly an integer.** Sonnet line 106 uses
  `log(avg_probs + 1e-10)`, so 3 codes used perfectly evenly out of 3 points
  gives **2.9999999991**, not 3. Asserting `== 3.0` would fail on the correct
  implementation; asserting `>= K` would fail for `K > M` (the ceiling is
  capped by the number of points, not by `K`).
- **D10 — β = 0.25 and the update is robust for β ∈ [0.1, 2.0]** (paper §3.2,
  verbatim), so the default is not load-bearing but must be exposed.

> **Recorded oracle bug — the stop-gradient is invisible in the value.**
> The first version of `vq_np_oracle.py` returned one combined scalar and
> differentiated it. FD disagreed at a **clean ratio of 1.25 = 1 + β on
> every single cell**. A clean constant ratio is the repo's standing signal
> for *"the harness differentiates the wrong function"*, not *"the gradient
> is wrong"* — so the analytic side was not touched; instead two
> stop-gradient-honouring functions were added (`total_for_fd_w`,
> `total_for_fd_z`) and FD agreed to `3.2e-11`. **A test whose oracle
> disagrees at a clean constant ratio is nearly always measuring the wrong
> function; check that before editing the implementation.**

## Task 4: GREEN — `VectorQuantizer` the Layer

**Objective:** wrap the free functions in a real `Layer`.

Implements all eight pure virtuals. **Note `VAE` never implements
`get_weights`/`get_gradients`, so it is abstract and was never instantiable** —
this layer must not repeat that.

- `forward()` returns the STE output (value `z_q`); caches `z_e`, `z_q`, indices.
- `backward()` returns `grad_output` (the STE identity) **plus** `β·d(commit)/dz_e`.
- `update_weights()` applies SGD to the codebook via the dictionary gradient.
- `parameters()` returns `{&codebook}`; `gradients()` returns `{&grad_codebook}`.
- Accessors: `codebook_loss()`, `commitment_loss()`, `perplexity()`,
  `indices()`, `usage_fraction()`.

**Run:** `./build/test_vq_vae` then `make build/test_vq_vae` at `-O2 -march=native`.

## Task 5: GREEN — `VectorQuantizerEMA`

**Objective:** the moving-average variant.

- `ema_cluster_size (K)`, `ema_w (D,K)`, `decay = 0.99`, `epsilon = 1e-5`.
- `update_weights()` performs the EMA step and **overwrites** the codebook.
- `update_weights(lr)` ignores `lr` — that is the whole point of EMA (the
  docstring in Sonnet says the update is optimizer-independent). Assert it.
- The dictionary term is dropped from the loss (D6).

## Task 6: GREEN — `VQVAE` end-to-end

**Objective:** compose encoder → quantizer → decoder into one `Layer`.

- `VQVAE(input_dim, hidden_dim, embedding_dim, num_embeddings, beta)`.
- `forward` returns the reconstruction; `backward` walks decoder → STE →
  encoder. `zero_grad`, `update_weights`, `parameters`, `gradients` delegate.
- A liveness test: the reconstruction must **differ from the identity**, and
  the total loss must fall over a few hundred steps on an easy fixture.

> **Recording the `advRob = 0.5000` lesson:** the training test asserts
> *liveness* (loss decreases, hidden mass non-zero, predictions split), not a
> convergence property that measurement may show is false. A model that
> predicts one class scores exactly `1/K` on a balanced task and reads as
> "half robust".

## Task 7: Mutation harness

**Objective:** prove the tests actually discriminate.

`tests/mutate_vq_vae.sh`, carrying **all seven** defences this repo has had to
learn the hard way (the adversarial session hit four of them in one script):

1. Baseline taken **once, before any mutation**, and **asserted pristine** by
   grepping markers that exist only in the correct implementation. *A harness
   that snapshots after mutating will eventually restore a mutant.*
2. **Relative** make targets plus an **mtime** check. `make /abs/path` reports
   "up to date" and never rebuilds — that produced 7 false `MUT-SURVIVED`.
3. `diff -q` after every `sed`; `MUT-NOOP` reported **separately** from
   `MUT-SURVIVED`. An edit that never applied is indistinguishable from a gap.
4. **`MUT-BROKEN`, never `MUT-CAUGHT`** — a compile error is not evidence.
5. The mutated object **excluded** from the link set (linking `LIB_OBJS` which
   already contains it double-defines every symbol and reports 8/8 caught).
6. `rm -f` intermediates before every build — stale `.o` files report build
   failures that do not reproduce.
7. **Verdicts counted from `[FAIL]` lines**, never from a summary string
   (whose format changes), and **inverted verdicts are impossible**: the run
   FAILS if `[FAIL]` count is zero for a mutation that should be caught.

Mutations to run: swap the two stop-gradients; drop `β`; drop the STE
identity; per-row mean instead of element mean; transpose the codebook; drop
the Laplace smoothing; last-wins tie-break.
