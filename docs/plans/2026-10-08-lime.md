# LIME Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.
> **Status: SHIPPED 2026-10-08** — 68/68 checks, 11/12 mutations caught, 12th provably equivalent.

**Goal:** Implement LIME — local linear surrogate explanations — completing the second method-family in the interpretability category and adding the one attribution method in this repo that uses **no gradients at all**.

**Architecture:** New header `include/nn/interpretability/lime.{h,cpp}` exposing a model-agnostic weighted-ridge fitter plus the LIME driver. `fit_local_surrogate` is the whole method: it takes the interpretable design matrix `Z`, the neighborhood responses `y`, the distances' kernel weights, and a ridge `alpha`, and returns `β, intercept, weighted R²`. `lime_explain` is the driver that builds the neighborhood (Gaussian perturbation in feature-standardized space, row 0 = the instance), computes distances, evaluates the black box in ONE batched forward, calls the fitter, and ranks features. Nothing calls `backward()` — the entire code path is inference + linear algebra, which is what makes it verifiable in closed form.

**Tech Stack:** C++17, repo `Tensor` (real-only 2-D), `Model`. Reuses `shapley.h`'s conventions: local xorshift64* (never `std::rand()`), logit-space attribution, zero-grad hygiene. No new dependencies, no LAPACK.

## Authoritative source verification (per writing-plans §3b)

Read from the reference implementations on 2026-10-08, **not from memory**:

**Kernel** — `lime/lime_tabular.py:245-253`:
```python
if kernel_width is None:
    kernel_width = np.sqrt(training_data.shape[1]) * .75
def kernel(d, kernel_width):
    return np.sqrt(np.exp(-(d ** 2) / kernel_width ** 2))
```
The `sqrt(exp(...))` is the load-bearing detail — the kernel value is `exp(-d²/2ω²)`, **not** `exp(-d²/ω²)`.

**Neighborhood** — `lime_tabular.py:475-540` + `explain_instance`:
- Continuous features: `data = N(0,1)·num_cols`, then `data*scale + mean` (`sample_around_instance=False` ⇒ perturb around the **training mean**).
- `data[0] = data_row.copy()` — **row 0 is the original instance**.
- Interpretable space is `scaled_data = (data - mean)/scale`. Not binary for continuous features (binary encoding is the categorical path, out of scope).
- `distances = euclidean(scaled_data, scaled_data[0])` — in **standardized** space; row 0 has distance exactly 0.

**Local fit** — `lime/lime_base.py:158-200`: `weights = kernel_fn(distances)`; `Ridge(alpha=1, fit_intercept=True).fit(Z, y, sample_weight=weights)`.

**Ridge semantics** — `sklearn/linear_model/_ridge.py` + `_base.py`:
- Objective `||y - Xw||² + alpha·||w||²` — **no `1/n_samples` normalisation**. Normal equations are `(XᵀWX + alpha·I)β = XᵀWy`.
- `fit_intercept=True` ⇒ `_preprocess_data` centers on the **sample-weighted** mean; `_set_intercept` restores `y_offset - X_offset·β`.
- `Ridge.score` = `1 - SS_res/SS_tot` with weights on both sums, `SS_tot` about the weighted mean of `y`.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| D1 | Expose `fit_local_surrogate(Z, y, weights, alpha)` as a **public, model-free** function taking columns as `vector<vector<double>>` | The method *is* the solve. Public ⇒ the core is testable in closed form without any `Model`, and reusable for a caller with their own neighborhood. `vector<vector<double>>` rather than a hardcoded pair so the signature matches the general case. |
| D2 | Ridge normal equations include `+ alpha·I`, no `1/n` scaling | Verified in sklearn source. Dropping it makes `alpha` inert. |
| D3 | Weighted-mean centering for the intercept | `_preprocess_data`. With LIME's kernel weights the distinction is material, not a rounding detail. |
| D4 | Continuous (Gaussian) mode only; no categorical/discretizer path | The discretizer path is a second, much larger feature. v1 is the closed-form-testable path. |
| D5 | Feature ranking = fit on all, rank by `|β|`, then **re-fit** on the top `num_features` | Matches `lime_base.py`'s two-stage `feature_selection` + `fit`. Re-ranking without re-fitting would report weights from a different fit. |
| D6 | Attributions on the **logit**, matching `attribution.h` / `shapley.h` | Repo-wide consistency; probabilities saturate. |
| D7 | Local xorshift64* + Box–Muller; never `std::rand()` / `std::normal_distribution` | `shapley.cpp` documents this repo's cross-suite RNG flakiness. |
| D8 | Zero parameter grads before and after | `Dense::backward` accumulates; uniform across all three attribution methods. |

## Closed-form oracle (why this is unusually testable)

For a **linear** black box `f(x) = Σ c_j x_j` (no bias) and neighborhood `raw[i][j] = z[i][j]·σ_j + μ_j`:
```
f(raw[i]) = Σ c_j σ_j z[i][j] + Σ c_j μ_j        (exactly affine in z)
```
so at `alpha = 0` the exact solution is
```
β_j = c_j·σ_j      β₀ = Σ c_j μ_j      g(z₀) = f(x)
```
for ANY neighborhood, ANY weights, ANY sample count — the kernel and the ridge only add variance and shrinkage on top of a problem that is already linear. That makes it a genuine oracle pinning the weighting, centering, intercept, perturbation scale, and distance metric at once.

**Necessary caveat, established by measurement (see Mutations):** exact recovery requires `alpha = 0`. At the reference default `alpha = 1` the coefficients are *deliberately* shrunk, so an exact-recovery assertion there tests the penalty, not correctness. Conversely, **the distance metric is unobservable at `alpha = 0`** — the exact solution is weight-independent, so the raw-vs-standardized mutation returns bit-identical `[100, 1]`/score 1. Distance is only observable *through* the ridge.

## Bugs found and fixed (both in first implementation, both found by tests)

1. **Box–Muller spare cached as a scaled integer.** The cached second variate was stored `static_cast<unsigned long>(r*sin(θ)*1e6)` and returned via `static_cast<double>(spare)` — the `1e6` went in and never came out. Every second draw was a ~1e20 value, so the neighborhood was astronomically large, all kernel weights but row 0 underflowed to 0, the centered normal equations became `0 = 0`, and the solve returned `β = 0` for every feature. Symptom looked like a ridge/ranking bug (all-zero coefficients, score 0 on a *perfectly linear* model); the tell was `z01=8` in a probe print where a standard normal belongs. **Lesson: cache a spare in the same type you return it in.**
2. **Partial-pivoting row swap swapped only the pivot element.** `std::swap(A[col*n+col], A[pivot*n+col])` left the rest of the pivot row in place, zeroing every solve that needed a swap. Fixed to swap the whole row.

## Test bugs found and fixed (impl was right in both cases)

1. **Hand-derivation omitted the centering.** The ridge-shrinkage test asserted the *uncentered* ratio `61/48`; the correct closed form is the centered one, `-4/23`. Verified numerically before transcribing.
2. **Null-buffer read.** The `num_features` test read `cfg.std[0][0]` on a `LimeConfig` that never set `std` — an empty `Tensor` whose subscript has no backing buffer (segfault, caught by ASan). Fixed to read the *echoed* `r.config.std`, which also exercises the echo.
3. **Degenerate oracle fixture.** The original instance sat **8.1σ** from the training mean against `ω = sqrt(4)·0.75 = 1.5`, so every sampled row landed >5 kernel widths away and all weights underflowed — effective sample size ≈ 1. Replaced with a ~1.4σ instance (a typical LIME query). The fixture now tests the method rather than the near-rank-deficient path.

### Two mutations that survived the first pass, and what each cost

Both were *invisible for a structural reason*, and both fixes are the general lesson:

- **Pivot swap.** Every pre-existing fixture produced a Gram matrix whose leading pivot was already maximal, so the swap branch never ran. Note the trap: with `n` samples the **centered** design has rank `≤ n−1`, so every 2-sample 2-column fixture is singular and *cannot* exercise pivoting. Fixed by a fixture searched for the property (`A = [[2, −5], [−5, 12.83]]`, `|−5| > |2|`, exact solution `β = (16, 7)`, `β₀ = −31`) with the forcing property asserted as a **precondition inside the test**, so it cannot silently degrade.
- **Distance metric.** At `alpha = 0` the exact solution is *weight-independent by construction*, so the raw-distance mutation returned bit-identical output. Measured: raw-distance gives the same `[100, 1]`, `local_pred 101`, `score 1`; at `alpha = 1` it collapses to `β = [0.154, 0.894]`, `score 0.287` vs the correct `[99.859, 0.9985]`, `score 0.999998`. Fixed by asserting the *ridge-shrunk* case — the discrimination only exists where the weights actually influence the answer.

### Provable non-coverage

Removing the final `zero_grad` is uncatchable because **nothing between the entry zeroing and it writes a parameter gradient** — `lime_explain` never calls `backward()` — so the two lines are behaviourally identical. The entry zeroing discards a caller's stale accumulated gradients; the exit one is defence in depth. The suite pins the observable contract (gradients are zero on return) rather than the line that delivers it. Recorded at the call site so a future reader does not "fix" a non-bug.
