# LIME Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Implement LIME — local linear surrogate explanations — completing the second method-family in the interpretability category and adding the one attribution method in this repo that uses **no gradients at all**.

**Architecture:** New header `include/nn/interpretability/lime.{h,cpp}` exposing a model-agnostic weighted-ridge fitter plus the LIME driver. `fit_local_surrogate` is the whole method: it takes the interpretable design matrix `Z`, the neighborhood responses `y`, the distances `d`, and a ridge `alpha`, and returns `β, intercept, weighted R²`. `lime_explain` is the driver that builds the neighborhood (Gaussian perturbation in feature-standardized space, row 0 = the instance), computes distances, calls the fitter, and ranks features. Nothing calls `backward()` — the entire code path is inference + linear algebra, which is what makes it verifiable in closed form.

**Tech Stack:** C++17, repo `Tensor` (real-only 2-D), `Model`. Reuses `shapley.h`'s conventions: local LCG (never `std::rand()`), logit-space attribution, zero-grad hygiene. No new dependencies, no LAPACK.

## Authoritative source verification (per writing-plans §3b)

Read from the reference implementations on 2026-10-08, **not from memory**:

**Kernel** — `lime/lime_tabular.py:245-253`:
```python
if kernel_width is None:
    kernel_width = np.sqrt(training_data.shape[1]) * .75
def kernel(d, kernel_width):
    return np.sqrt(np.exp(-(d ** 2) / kernel_width ** 2))
```
Note the `sqrt(exp(...))` — the kernel value is `exp(-d²/2w²)`, **not** `exp(-d²/w²)`. A plausible-looking `std::exp(-d*d/w)` is a factor-of-2-in-the-exponent bug that no amount of eyeballing catches.

**Neighborhood** — `lime_tabular.py:475-540` (`__data_inverse`) + `explain_instance`:
- Continuous features: `data = N(0,1)·num_cols`, then `data*scale + mean` (default `sample_around_instance=False`, i.e. perturb around the **training mean**, not around the instance).
- `data[0] = data_row.copy()` — **row 0 is the original instance**.
- Interpretable space is `scaled_data = (data - mean) / scale`, i.e. the *standardized* continuous value. It is **not** binary for continuous features (binary encoding is the categorical/discretized path, out of scope — see D4).
- `distances = euclidean(scaled_data, scaled_data[0])` — so the distance metric lives in **standardized** space and row 0 has distance exactly 0.

**Local fit** — `lime/lime_base.py:158-200` (`explain_instance_with_data`):
```python
weights = self.kernel_fn(distances)
easy_model = Ridge(alpha=1, fit_intercept=True, random_state=...)
easy_model.fit(neighborhood_data[:, used_features], labels_column, sample_weight=weights)
prediction_score = easy_model.score(..., sample_weight=weights)
local_pred = easy_model.predict(neighborhood_data[0, used_features].reshape(1, -1))
```

**Ridge semantics** — `sklearn/linear_model/_ridge.py`:
- Objective is `||y - Xw||² + alpha·||w||²` — **no `1/n_samples` normalization**. The normal equations are `(XᵀWX + alpha·I)β = XᵀWy`. Dropping `+alpha·I` makes the `alpha` parameter a no-op and silently turns this into OLS.
- `fit_intercept=True` → `_preprocess_data` centers `X` and `y` by the **sample-weighted** mean (`X_offset`, `y_offset`), and `_set_intercept` restores `intercept = y_offset - X_offset·β`. Centering by the *unweighted* mean is a different regression problem when the kernel weights are far from uniform — which they always are, since row 0 has weight 1.0 and distant samples have weight ≈ 0.
- `Ridge.score` is `1 - SS_res/SS_tot` with the weights applied to both sums, where `SS_tot` uses the **weighted** mean of `y`.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| D1 | Expose `fit_local_surrogate(Z, y, distances, alpha)` as a **public, model-free** function | The method *is* the solve. Making it public means the core is testable in closed form without any `Model`, and it is reusable (a user with their own neighborhood can fit a LIME surrogate directly). |
| D2 | Ridge normal equations include `+ alpha·I` (no `1/n` scaling), matching sklearn | Verified above. Getting this wrong makes `alpha` inert. |
| D3 | Weighted-mean centering for the intercept | sklearn's `_preprocess_data`. With LIME's kernel weights the distinction is not a rounding detail. |
| D4 | Continuous (Gaussian perturbation) mode only; no categorical/discretizer path | The discretizer path (`BaseDiscretizer`, quartile bins, `undiscretize`) is a second, much larger feature. v1 is continuous-only, and it is the closed-form-testable path. |
| D5 | Feature ranking is the `highest_weights` variant: fit on all features, rank by `|β|`, then **re-fit** on the top `num_features` | Matches `lime_base.py`'s two-stage `feature_selection` + `fit`. `num_features >= M` skips selection entirely. |
| D6 | Attributions are on the **logit**, same convention as `attribution.h` / `shapley.h` | Repo-wide consistency; probabilities saturate. |
| D7 | Local LCG + Box–Muller; never `std::rand()`/`std::normal_distribution` | `shapley.cpp` documents this repo's cross-suite RNG flakiness (`test_adaln_zero` intermittent NaN in NOT_FIXED.md). Determinism per seed is a shipped property, pinned by a test. |
| D8 | `lime_explain` zeroes parameter grads before and after | `Dense::backward` accumulates; LIME never calls backward, but a caller may have run a training step first, and the invariant "attribution leaves no residue" is worth holding uniformly across all three methods. |

## Closed-form oracle (the property that makes this testable)

For a **linear** model `f(x) = Σ_j c_j x_j` (no bias) and the default `sample_around_instance=false` neighborhood, the perturbed row is
```
raw[i][j] = z[i][j]·σ_j + μ_j
```
so `f(raw[i]) = Σ_j c_j z[i][j] σ_j + Σ_j c_j μ_j`. The response is therefore **exactly linear in the interpretable coordinates**, and the exact ridge solution is

```
β_j = c_j · σ_j          intercept = Σ_j c_j · μ_j
local_prediction = Σ_j β_j·z[0][j] + intercept = Σ_j c_j x_j = f(x)
```

This holds for any neighborhood, any kernel weights, and any number of samples — the kernel and the ridge only add variance and shrinkage on top of a problem that is already linear. That makes it a genuine oracle: it pins the weighting, the centering, the intercept, the perturbation scale, and the distance metric all at once. A bug anywhere in that chain moves the answer.

## Out of scope (v1)
- Categorical features / the discretizer path (`BaseDiscretizer`, quartile bins) — see D4.
- Image LIME (`lime_image`) — needs superpixels, not a 2-D dense tensor.
- `lasso_path` and `forward_selection` feature selection — D5 uses `highest_weights`.
- Non-euclidean distance metrics — only euclidean is meaningful in a standardized dense space.
- Regression targets (multi-column output is out of scope; `target` selects one column).

## Mutation targets (pre-registered, so the result is not cherry-picked)

| Mutation | Expected to be caught by |
|---|---|
| Drop `+ alpha·I` from the normal equations | the closed-form oracle at `alpha > 0` (coefficients shrink toward 0) |
| Kernel `exp(-d²/w²)` instead of `sqrt(exp(-d²/w²))` | kernel values + oracle (weights too flat) |
| Unweighted mean centering | closed-form oracle (intercept and β shift) |
| Perturb around the instance instead of the training mean | closed-form oracle (β becomes `c_j·σ_j` only for the around-mean variant) |
| Row 0 not replaced by the instance | `local_prediction` test + oracle |
| Distance computed in raw rather than standardized space | distance test with unequal per-feature σ |
| Rank by `β` rather than `|β|` | ranking test with a negative-dominant feature |

**Provable non-coverage (record, do not chase):** `+alpha·I` applied as `alpha·I·n_samples` instead of `alpha·I` is only distinguishable via the ridge shrinkage magnitude, which the closed-form oracle pins — so it *is* covered. Conversely, a mutation that swaps the two Box–Muller outputs changes the *sample stream* but not the answer's distribution; it is caught only by a determinism-vs-known-stream test, which is fragile by construction. Recorded as expected non-coverage.
