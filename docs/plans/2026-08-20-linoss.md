# LinOSS Implementation Plan (Orvieto et al. 2024/2025)

> **For Hermes:** Use test-driven-development skill. Build test-first.

**Goal:** Implement LinOSS, a clean stable-by-construction state space layer based on linear oscillators, in `include/nn/layers/recurrent/linoss.{h,cpp}`.

**Architecture:** Two flavors — IM (Implicit Midpoint, A-stable) and HE (Heun's explicit). Both use a per-channel complex state that can be written as two real oscillators (real & imaginary parts) of size `2*d_osc`. Closed-form transition matrix per timestep makes the recurrence numerically stable without any discretization trick.

**Tech Stack:** C++17, Tensor class, existing optimizer/Layer patterns. Two new layers (IM-LinOSSCell, HE-LinOSSCell) plus a wrapper LinOSSModel that stacks them.

## Paper reference

Orvieto, Smith, Gu, Fernando, Goyal, et al. "From Principles to Learning Systems: State Space Models That Need No Discretization" (LinOSS), ICLR 2025. https://arxiv.org/abs/2410.03943

## Core idea

A state space ODE: `x'(t) = A x(t) + B u(t)` with `y(t) = C x(t)`.

LinOSS restricts A to be a **diagonal-stable-by-construction** matrix of size `2*d_osc × 2*d_osc` consisting of `(d_osc)` independent 2×2 blocks, each representing a damped oscillator:

For block k:
```
A_k = [[ -exp(λ_k),      ω_k ],
       [    -ω_k,    -exp(λ_k) ]]
```
where `λ_k` controls damping (exp(λ_k) > 0) and `ω_k` is the natural frequency. The block's eigenvalues are `-exp(λ_k) ± i·ω_k`, so the continuous-time system is **exponentially stable** by construction.

B is a per-channel learnable `(2*d_osc, d_input)` matrix; C is `(d_output, 2*d_osc)`.

Two discretization flavors:
- **IM-LinOSS** (implicit midpoint): implicit, A-stable for any step size. Solve `(I - dt/2 · A) x_{k+1} = (I + dt/2 · A) x_k + dt · B u_k` via block-diagonal 2×2 inversion.
- **HE-LinOSS** (Heun's method): explicit but stable for small dt.

Both flavors share the same A, B, C parameters and differ only in the step update.

For tractability of gradient checks at small T (T≤8), we **expose dt as a learnable parameter** (per-channel scalar, size `d_osc`) and keep the per-step transition computation explicit (no FFT, no parallel scan, just a for-loop over T).

## Public API

```cpp
enum class LinOSSType { IMPLICIT_MIDPOINT, HEUN };

class LinOSSCell : public Layer {
public:
    // d_input, d_output, d_osc (number of oscillator pairs → state dim = 2*d_osc)
    LinOSSCell(int d_input, int d_output, int d_osc, LinOSSType type = LinOSSType::IMPLICIT_MIDPOINT);

    Tensor forward(const Tensor& input) override;  // (T, d_input) → (T, d_output)
    Tensor backward(const Tensor& grad_output, double learning_rate) override;
    void update_weights(double learning_rate) override;
    void zero_grad() override;
    Tensor get_weights() const override { return B; }
    Tensor get_gradients() const override { return grad_B; }
    std::vector<Tensor*> parameters() override;
    std::vector<Tensor*> gradients() override;
    std::string name() const override { return "LinOSSCell"; }

    // Reset recurrent state for FD re-evaluations
    void reset_state();

    // Learned parameters (public for FD gradient checks)
    Tensor B;             // (d_input, 2*d_osc) — input projection
    Tensor C;             // (2*d_osc, d_output) — output projection
    Tensor log_damping;   // (d_osc,) — per-osc damping log (real & imag share damping)
    Tensor freq;          // (d_osc,) — per-osc natural frequency
    Tensor log_dt;        // scalar — log step size
    Tensor bias;          // (d_output,) — output bias

    // Gradients
    Tensor grad_B, grad_C, grad_log_damping, grad_freq, grad_log_dt, grad_bias;

    LinOSSType type_;
    int d_input_, d_output_, d_osc_;
};

class LinOSSModel : public Layer {
public:
    LinOSSModel(int d_input, int d_output, int d_model, int num_layers, int d_osc, LinOSSType type);
    // input (T, d_input) → output (d_output,) (last-step classifier)
    Tensor forward(const Tensor& input) override;
    Tensor backward(const Tensor& grad_output, double learning_rate) override;
    // ...
};
```

## Numerical notes

For IM-LinOSS, the implicit midpoint update for one 2×2 block at step k is:
```
x_k^+ := (I + dt/2 · A) · x_k + dt · B_block · u_k
x_{k+1} = (I - dt/2 · A)^{-1} · x_k^+
```
For a 2×2 block `A_k = [[-e^λ, ω], [-ω, -e^λ]]`:
```
det = e^{2λ} + (dt/2)^2 (e^{2λ} + ω^2) + dt · e^λ
```
Wait — the implicit midpoint rule is:
```
x_{k+1} - x_k = dt · [A · (x_k + x_{k+1})/2 + B · u_k]
```
Rearranging:
```
(I - dt/2 · A) x_{k+1} = (I + dt/2 · A) x_k + dt · B u_k
```
With `M = I - dt/2 · A`, this gives:
```
M_{k+1} = M^{-1} [M + dt · A] x_k + dt · M^{-1} B u_k
```
This is a **closed-form 2×2 matrix inversion** per block. For a 2×2 matrix `[[a, b], [c, d]]`, the inverse is `(1/det) [[d, -b], [-c, a]]`.

For HE-LinOSS (Heun's method):
```
x_hat = x_k + dt · [A · x_k + B · u_k]
x_{k+1} = x_k + dt/2 · [(A · x_k + B · u_k) + (A · x_hat + B · u_{k+1})]
```
The trapezoidal average between the explicit predictor and the re-evaluated slope.

Both are stable; IM unconditionally A-stable, HE conditionally stable.
