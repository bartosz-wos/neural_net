# Inference-Time KV Cache Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Ship an inference-time key/value cache for the repo's transformer stack, and wire it into the canonical `MultiHeadAttention` so that token-by-token decoding produces the *same* output as the full-sequence forward pass.

**Architecture:** Two pieces.
1. `nn::utils::KVCache` (`include/nn/utils/kv_cache.{h,cpp}`) — a layer-agnostic, preallocated, per-layer K/V store. It owns no attention maths; it owns *bookkeeping* (length, capacity, reset) and the storage.
2. `MultiHeadAttention::forward_cached` (`include/nn/layers/attention/transformer.{h,cpp}`) — the consumer. The existing `forward()` is untouched; the cached path is a separate, explicit entry point so there is no ambiguity about whether an input is a full sequence or an increment.

**Tech Stack:** C++17 (repo's `-std=c++17 -O2 -Wall -Wextra -march=native`), float64 numpy oracle, bash mutation harness, ASan+UBSan.

## THE GAP, MEASURED (2026-11-16)

```
grep -rinE '\bkv.?cache|paged.attn|prefix.cache|past_key' include/
  -> 3 hits, ALL COMMENTS (mla.h:33, sliding_window.h:17, megalodon.h:67)
```
ZERO implementation across ~250 layers. Many attention layers hold `last_k_`/`last_v_` for **backward** — that is NOT an inference-time cache. The repo has no incremental decoding path at all: every transformer forward is O(T^2) over the whole sequence, so autoregressive generation re-computes the entire prefix at every step.

**THE TRAP THIS PLAN AVOIDS:** `grep -ril 'kv_cache'` hits the backward caches and reports the feature as PRESENT. The absence was measured with the matching lines printed.

## THE INVARIANT THAT MAKES THIS FEATURE CORRECT

For a causal attention, decoding one token at a time with a cache must equal the full-sequence forward, **token for token**. That is the property the suite pins, and it is stronger than "approximately equal": the arithmetic is performed in the same order in both paths, so the two are expected to agree to the last bit. A test that only checks "close enough" would pass a cache that attends to the wrong tokens.

## THE NON-VACUITY REQUIREMENT

A cached path that silently ignores the cache produces the right answer for step 0 and the wrong one for every later step — but only if the test compares against a full forward. The suite must ALSO prove the cache is *read*: perturbing token 0 must change the output of step 5. Otherwise a test that "passes" because both paths are broken in the same way is possible.

### Task 2: Measure the oracle's own sensitivity — `tests/kv_cache_mutate_oracle.py`

**Objective:** A green oracle proves nothing until it is shown to FAIL when broken.

**Files:**
- Create: `tests/kv_cache_mutate_oracle.py`

**Step 1: Write the harness**

It edits the oracle's model code in specific, named ways and requires the oracle to fail each time. The mutations must break the MODEL, not delete a CHECK (a mutation that removes the thing that would catch it measures nothing):

- M1: the incremental path ignores the cached keys (attend only to the new chunk);
- M2: the incremental path ignores the cached values (attend to new values only);
- M3: the causal mask is dropped in the incremental path;
- M4: the causal mask is applied to the full path as well (wrong direction);
- M5: the `sqrt(d_k + 1e-9)` scale is replaced by `sqrt(d_k)`;

- M10: the per-head isolation is broken (heads are summed);
- M11: the output projection is skipped;

## WHAT THE SESSION ACTUALLY FOUND, BEYOND THE FEATURE

**THE FEATURE EXPOSED A REPO-WIDE BUILD BUG, AND THAT WAS THE MOST
VALUABLE FINDING OF THE SESSION.**

Adding three members to `MultiHeadAttention` changed that class's LAYOUT.
`test_mha_backward` then SEGFAULTED with no output at all -- in a suite
that touches none of the changed code. The natural reading ("my refactor
broke it") was WRONG, and the controlled experiment settled it:

| build | result |
|---|---|
| pre-work tree (`c3215a1`) with the change reverted | **10 passed, 0 failed** |
| the change applied | **SEGFAULT (rc=139), no output** |
| the same sources, compiled FRESH under ASan | **10 passed, 0 failed** |

A crash that reproduces only with STALE objects is a BUILD problem, not a
code problem -- and a stale object is invisible to every source-level
tool, which is why the third row is the decisive one.

The cause: the Makefile's DEPS list used
`$(patsubst tests/%.cpp,$(BUILD_DIR)/test_%.d,...)`, and the test files
are already named `test_*.cpp`, so the prefix was DUPLICATED: it asked
for `build/test_test_mha_backward.d` while the file lives at
`build/test_mha_backward.d`. **289 of the 289 test dependency files were
named wrong, and NONE of the wrong names existed on disk** -- a missing
file in an `-include` is silently ignored, so **no test object in this
repo had ever been rebuilt on a header change.** The library objects were
unaffected (their DEPS names are correct), so the two halves of a link
could disagree about a class layout: exactly the ODR violation the
Makefile's own header comment warns about at length.

**THE FIX IS ONE LINE** (`$(patsubst tests/%.cpp,$(BUILD_DIR)/%.d,...)`),
and the whole suite now runs against FRESH objects for the first time in
this repo's history.

**THE GENERALISATION: a build system that silently ignores a missing
dependency file is worse than one that has no dependency tracking at
all, because the failure it produces (an ODR violation) surfaces in a
completely unrelated place.** A `grep` for the `.d` file's name would have
found it in one step; nothing in the normal build output points at it.

## WHAT WAS NOT DONE, AND WHY

- **A `TransformerBlock`-level cached decode.** It needs a RESIDUAL-STREAM
  cache as well as the attention cache, because the block's residual
  carries the prefix. That is a separate feature, and shipping a
  half-working block-level decode would be worse than shipping none.
- **A block-level `forward_cached` for `TransformerDecoder`, `ViT`, `GPT`
  and the rest of the stack.** Each of those layers has its own attention
  path; the cache is now available to them, but wiring each one is its own
  change, and each one needs its own equivalence test.
- **An eviction policy.** Deliberately absent: a cache that silently drops
  the oldest tokens CHANGES the model's output. The capacity is a hard
  bound and exceeding it is an ERROR.
